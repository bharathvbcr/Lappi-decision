### The floor is computed, and the computation is checked

Asserting "the loss fell" proves nothing — rung 0's whole lesson. So the tool computes the
conditional label entropy of each channel given **what the model actually conditions on**: the
letter floor groups by the exact prefix `tokens[i, :target_index[i] + 1]`, the span floor groups
the two pointers separately over `2K` decisions to match the head's own `"mean"`.

For this corpus both floors are **0.0** — which is a number a wrong formula would also produce.
So the tool also trains a **deliberately colliding** corpus, two choice rows sharing a prefix
with different golds:

| corpus | computed floor | run stopped at | gap | row |
| --- | --- | --- | --- | --- |
| clean | 0.000000 | 0.007077 | 0.0071 | (the six above) |
| colliding | **0.173287** | **0.180570** | 0.0073 | `1e6a1ebb-91d3-47ad-8a36-882e59402f0e` |

Same slack, non-zero floor. The formula is exact, not assumed, and `FLOOR_SLACK = 0.05` is
calibrated against a case where "reached the floor" and "reached zero" are different sentences.

## 3. Where the abstention decoded, for every slot kind

Read the way `crates/qd-runtime/src/answer.rs` reads it —
`noul_row = plan.rows - RESERVED_NOUL_ROWS` — and **never from the loss**.

| slot kind | rows | noul row | how it is decoded | abstaining rows correct |
| --- | --- | --- | --- | --- |
| `choice` | 5 (4 options + 1) | 4 | `QueryKind::Letters`: `lm_head` logits at this slot's rendered letters, argmax | 1/1, all 4 rows correct |
| `score` | 6 (5 bins + 1) | 5 | the same letter slice — **plain cross-entropy, no ordinal loss** | 1/1, all 4 rows correct |
| `span` | 4 (3 lines + 1) | 3 | `PointerStart`/`PointerEnd` through `heads.serving_scores` | 1/1, all 4 rows correct |

Identical on all six runs. The row order is not restated in the tool: `_render_row_order` builds
a real `qd_data.schema.Request` and calls `qd_data.render.render`, then reads the letters out of
the `SlotRender` the renderer produced — `choice=['A','B','C','D','Z']`,
`score=['A','B','C','D','E','Z']`, `span=['Z']`. A second copy of "A..P then Z" in a tool would
be free to drift from the renderer, and the drift would look exactly like a correct tool.

**The score slot got plain cross-entropy through `fused_linear_cross_entropy`, the same loss the
choice slot got.** No CORAL, no cumulative, no ordinal anything, because none exists on either
side — `GAP-TRAINER-SCORE-SLOT-HAS-NO-ORDINAL-LOSS`, still open, still not this lane's to
implement. The score arm above is a statement about the **letter channel**, not about an ordinal
head that does not yet exist. Decide that gap before a score slot is trained for real.

### Why the loss cannot see this — and here, not even in principle

rung 0 demonstrated the span counterfactual: a head trained abstain-**first** reached **0.0**, a
*better* floor than the correct 1.43e-06, and the runtime then answered "line ordinal 0" for
every no-evidence case.

The letter channel is worse, and the demonstration is sharper. `ft_supervision` routes `choice`
and `score` through plain next-token cross-entropy over the **vocabulary**. That channel never
sees a row at all; the row set is assembled at serve time from the slot's rendered letters. So
this tool does not need two training runs. It reads **one** trained model under two row orders:

| row order | letter abstentions decoded as abstain | span abstention | what the runtime answers for a no-evidence choice |
| --- | --- | --- | --- |
| noul **last** (as `_slot_suffix` renders) | **2/2** | 1/1 | **abstain** |
| noul **first** (the defect) | **0/2** | 1/1, unchanged | **option ordinal 0** |

The loss is not merely uninformative about the difference — **it is the same number, because it
is the same run.** Recorded as `GAP-FT-LETTER-CHANNEL-ABSTAIN-ROW-UNPINNED-ON-THE-TRAINING-SIDE`.

The span abstention is *unchanged* between the two arms, and that is asserted rather than
ignored: reordering the letters must not move a pointer row, and an arm that moved it would
differ in more than the thing under test.

## 6. Rule 4: nothing was launched, and here is what the GPU decision now rests on

Nothing ran on rented hardware. `CostEstimate(usd_per_hour=0.0, n_gpus=0)` is a measured fact
about a Mac that is already bought, not a way around the rule: a rented run sets a real rate and
`RunControl` refuses to start without `approved_by`.

What this lane changes about the decision:

* **The S4 FT loop is no longer NOT RUN.** It executes, converges to the floor its data admits,
  and its three slot kinds decode where the runtime reads them. The wiring bug that an 8xH100
  run would have discovered expensively is the one class this now rules out cheaply.
* **It still proves nothing about the 2B model.** No Qwen weights were loaded, no real tokenizer,
  no shards, no `remap`. The corpus is 12 synthetic rows and the model is a toy transformer built
  in the tool. `Qwen3_5ForCausalLM.from_pretrained` dropping the 297 vision and 15 mtp tensors
  remains verified **only by reading the transformers source** — this lane did not load the
  model and does not close that.
* **`RunControl`'s rule-4 mechanism is still unexercised against a real rate**, for the same
  reason the TRAINER lane gave: no run has ever had one.

### What remains before a GPU job is justified

1. **Close `GAP-FT-SHARD-DOOR-DOES-NOT-CHECK-THE-PATH`** (5.1). A rented run reading held-out
   shards through a mis-pointed writer is a rule-3 violation that costs the whole run's evidence,
   and the fix is a required keyword and one call. **This is the blocking one.**
2. **Decide `GAP-FT-LETTER-CHANNEL-ABSTAIN-ROW-UNPINNED-ON-THE-TRAINING-SIDE`** (5.2) — where the
   letter row layout lives. Cheap now, and a checkpoint trained before the decision is not
   comparable to one trained after if the answer changes the objective.
3. **Decide `GAP-TRAINER-SCORE-SLOT-HAS-NO-ORDINAL-LOSS`** before any score slot is trained, for
   exactly the same reason. `docs/schema-api.md:107` says cumulative/CORAL; the code says plain
   cross-entropy; one of them is wrong and it is not this lane's call.
4. **Run the same treatment one rung up: real shards, real tokenizer, real `remap`, on one GPU.**
   Everything above was established on a toy vocabulary. The mapping this tool could not exercise
   is the line→token one — `GAP-SPAN-HEAD-LINE-MAPPING-BPE-UNVERIFIED`, and the sibling lane's
   finding that the span head refuses three fifths of real code. A single-GPU job under $20 needs
   no human yes; **8xH100 does, and this lane is not asking for one.**
