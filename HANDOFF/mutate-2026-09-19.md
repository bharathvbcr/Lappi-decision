## The span guarantee — how it is actually enforced

Two derivations, sharing the convention and no code path:

- **A** — `span::span_from_byte_range` over the byte range `EditSet::apply` reports it wrote.
- **B** — `diffspan::span_from_text_diff`, handed only the before and after text.

`generate::build_example` computes both on **every** example and drops the example when they differ,
counting it under `totals.span_disagreements`. Measured over the demonstration pool and over every
adversarial fixture: **0**.

Three things made them agree for the right reason rather than by accident:

1. `ops::body_line_region` — a block body's interior begins immediately *after* `{`, so an edit
   starting there makes A report the **signature** line while B reports the line below. Every `stub`
   operator now edits from the first line the body actually owns. This is the single most
   load-bearing helper in the crate; `ops::tests::a_block_body_region_starts_on_the_line_after_the_brace`
   and its Python and single-line siblings pin it.
2. `ops::snap_if_line_owned` — `edit::snap_to_lines` widens each end independently, which for a
   `} else { … }` sitting after code swallows the trailing newline and joins two untouched lines.
   Both ends snap together now, or neither does.
3. `Refusal::NoTextualChange` is **separate from** `SpanDisagreement`. A no-op candidate is a routine
   decline; a span disagreement is the alarm. Counting the first as the second would bury the alarm
   in noise. (This was a live defect — see `## Bugs found in the existing code` (2).)

`tests/span_convention.rs::a_replacement_that_rewrites_a_line_to_itself_is_a_disagreement_and_must_stay_one`
pins the one case where A and B legitimately differ, with the reasoning: teaching A to trim unchanged
leading lines would make it converge on B's algorithm, and two derivations sharing an algorithm are
one derivation with extra steps.

## The placement rule, and the number that is carried separately

The hunk check runs in **pre-mutation coordinates** (`Example.source_span`), because `hunks` are
lines of the agent's post-image file and the span label is over the post-*mutation* file. Comparing
the two directly would be off by however many lines the mutation added — exactly the class of error
this crate exists to keep out.

`hunks` is `Option`. When a record carries none, the example is stamped `hunk_constrained: false` and
counted in `totals.examples_without_hunk_constraint`, **separately from** the constrained ones. An
unconstrained example is not a constrained one and the sum of the two is not "examples that landed in
the hunk". A site outside every hunk is skipped, never relocated (`Refusal::OutsideHunk`).

## Split safety

`Example.function` carries `(repo, path, symbol, arity)` on **every** row — not a diff hash, which
moves when the layout does. Mutated-or-clean is decided by `sha256(seed ‖ "disposition" ‖ repo ‖
path)`, keyed on the **file**, so two pool records touching the same file always land on the same
side and one function can never appear both ways. `Refusal::SplitConflict` exists as a loud backstop
that should never fire; `generate::tests::one_file_never_appears_both_mutated_and_clean` asserts it
does not.

The actual split still happens in `python/qd_data`. This crate's job is to emit the identity, and it
does.

## Determinism

`ChaCha20Rng::from_seed(sha256(seed.to_le_bytes() ‖ record.id))` — **per record**, so output does not
depend on how many records came before. That is what makes `--limit` and `--language` give the same
examples for the records they do process
(`generate::tests::a_limit_caps_the_output_without_changing_what_precedes_it`).

`tests/determinism.rs` runs the **binary** twice and compares the emitted JSONL byte for byte, the
manifest byte for byte, and the printed digest — because what the ledger hashes is a file on disk and
the steps between the library and that file are where a timestamp gets in. The manifest carries **no
wall clock at all**, and a test asserts the strings `timestamp`, `generated_at` and `created_at`
appear nowhere in it.

## Bugs found in the existing code

1. **`go_lang::else_branches` produced diffs that do not parse.** tree-sitter-go's `alternative`
   field points at the block **after** the `else` keyword, which is a separate preceding token
   (verified against tree-sitter-go 0.23.4 with a grammar probe). Removing only the node left a
   dangling `} else`, shipped under a confident `logic.drop_else` label. Fixed by introducing
   `ElseSite`, which makes each language state its own removable range instead of an operator
   guessing from a node kind it does not own. Test:
   `ops::tests::dropping_a_go_else_takes_the_keyword_with_the_block` — verified to fail against the
   pre-fix code (it left `} else` behind).

2. **A no-op candidate inflated the span-disagreement counter.** `stub.hardcoded` derives its value
   from a literal already in the function, so on `fn one_line() -> u32 { 3 }` — whose only literal
   *is* its body — it rewrote `3` to `3`. The generator caught the empty diff but filed it under
   `SpanDisagreement`, the one counter that must stay clean. Fixed in two places: `replace_body`
   declines a no-op at generation, and the backstop now files under `Refusal::NoTextualChange`. Test:
   `ops::tests::a_no_op_stub_candidate_is_declined_at_generation` — verified to fail against the
   pre-fix code (it offered `single-line body replaced with \`3\``).

3. **`cosmetic.rename_local` could rewrite a closure parameter that shadows the local.**
   `Language::local_bindings` stops at a function boundary, so a closure's parameters are counted as
   bindings nowhere — which makes
   `fn f() { let v = 1; let bump = |v: usize| v * 2; }` look like a name bound exactly once whose
   occurrences are all inside the body. The rename rewrote all five occurrences, including the
   parameter, and shipped it as behaviour-preserving. Fixed by refusing any name with an occurrence
   inside a nested function scope. Test:
   `ops::tests::a_local_shadowed_by_a_closure_parameter_is_not_a_rename_candidate` — verified to fail
   against the pre-fix code (it offered ``local `v` renamed to `tmp` at 5 sites``).

4. **`cosmetic.reformat` could emit a hunk that does not parse in isolation.** A whole-file reformat
   can move a token across a line boundary; the alignment splits that into two hunks and applying
   either alone unbalances the file. Caught by the adversarial suite as
   `mutation_did_not_parse=1` on a Swift fixture. Narrowed — see
   `GAP-MUTATE-REFORMAT-NARROWED-TO-WHITESPACE`.

All four were found by the adversarial corpus or by a unit test written against the operator
directly, not by reading. The first version of the shadowed-rename test went through the generator
and **passed against the buggy code**, because the weighted draw never picked that candidate; it was
rewritten to drive the operator directly.

## Where the spec turned out wrong

1. **The span wire format did not match the runtime's, despite the spec saying it did.**
   `docs/mutation-operators.md` says line numbers are "in the same convention the runtime's `span`
   slot returns". The *numeric* convention matched (1-based, inclusive; `qd-runtime/src/answer.rs`
   does `top + 1`). The **field names did not**: this crate emitted `{"start","end"}` while
   `qd-runtime/src/schema.rs:196-201` declares `SpanValue{start_line,end_line}` with
   `#[serde(deny_unknown_fields)]`, and `docs/schema-api.md` and `python/qd_data/schema.py` both
   spell it `start_line`/`end_line`. Every training row's span would have failed to deserialize on
   all three surfaces. Fixed here by renaming only the serde representation. No consumer of the old
   spelling existed, so this was latent rather than live. `GAP-MUTATE-SPAN-WIRE-NAMES`.
   **Knock-on for the next lane: pool `hunks` are now `{"start_line","end_line"}` too.**

2. **The two specification documents disagree about `cosmetic.reorder_imports`.**
   `docs/mutation-operators.md` shrinks the no-formatter set to `edit_comment` and a provably-safe
   `rename_local`; `docs/hardening.md` §1 words the same shrink as "comment text, import order within
   a group". Implemented the narrower reading — the document this lane was told is its specification
   — and recorded it rather than resolving it silently in our favour.
   `GAP-MUTATE-DOC-CONFLICT-REORDER-IMPORTS`. **Needs a human decision.**

3. **The facade in the spec is a sketch, and two signatures had to change.** The spec's
   `else_branches` returns `Vec<Node>`; that shape is what caused bug (1) above, because the
   removable range is not always the node's own extent. It now returns `Vec<ElseSite>`, matching the
   idiom `ErrorSite`/`SyncSite` already established in `lang/mod.rs`. Two methods were added for the
   same reason: `statement_texts` (so the already-a-stub check can be language-agnostic without
   operators importing each language module) and `early_return` (Rust's `stub.default_return`
   replacement body is the tail expression `Ok(())`, which is not a statement and cannot be inserted
   above live code — the other four spell both the same way).

4. **Swift's grammar overloads the `name` field harder than the spec anticipates.** On a
   `function_declaration`, the function's identifier, *each parameter's type* and *the return type*
   all arrive under the field name `name` (verified against tree-sitter-swift 0.7.3 with a probe).
   `child_by_field_name("name")` answers the identifier and nothing else useful; the return type has
   to be found positionally as the named node after the `->` token. Getting this wrong hands
   `stub.default_return` the wrong type to zero — a poisoned label, not a compile error. Pinned by
   `swift_lang::tests::the_return_type_is_the_node_after_the_arrow_not_the_first_name_field`.

## The adversarial corpus — what is defended and what is not

Every row of `docs/hardening.md` §1 has a test in `tests/adversarial.rs`. Two invariants are asserted
on **every** example any test in that file produces: the recorded span is what a fresh textual diff
implies and is inside the file, and the mutated text still parses as the language it claims to be.
The second is what turns "only where removal still parses" from a per-operator promise into a
pipeline guarantee.

| Attack | Defended | How |
| --- | --- | --- |
| CRLF line endings | yes | normalized, `normalization.crlf` recorded on every example; no `\r` survives |
| Mixed CRLF/LF | yes | flagged separately from "merely converted" — this is where offsets diverge mid-file |
| UTF-8 BOM | yes | stripped and recorded; asserted not to shift line 1 |
| Multi-byte identifiers, emoji | yes | Japanese identifiers and emoji in comments and strings; spans hold |
| String literal containing `todo!()` | yes | the already-a-stub check works on **statement nodes**, never a file substring |
| Comment containing the construct | yes | same mechanism; tested in Rust and Python |
| Nested functions | yes | offered as their own body, `is_nested: true`, `node_kind` recorded |
| Closures / lambdas | yes | `walk_body` stops at the boundary; sites never attributed to the outer body |
| Trait default bodies | yes | mutated; a bare signature is not |
| `async fn`, generics with `where` | yes | asserted no mutation lands above the body's first line |
| Macros with braces | yes | same fixture |
| Body already `todo!()` | yes | every stub operator refuses; refusal recorded |
| Empty body / no body | yes | skipped in all four languages that have the shape |
| Single-line function | yes | in-place mutations assert `span.start == span.end` |
| No trailing newline | yes | asserted span end ≤ total lines |
| 0-byte, 1-byte file | yes | `empty_source` / `parse_errors` by name |
| 10 MB file | yes | `too_large` — refused by size, not discovered as a timeout |
| 1000-level nesting | yes | exactly one bounded refusal, no stack overflow (every walk uses an explicit stack) |
| ERROR nodes | yes | refused in all five languages |

### Cases I could **not** fully defend

- **`logic.swallow_error` and `logic.swap_args` produce diffs that parse but may not compile.**
  Rust's `?` → `.unwrap_or_default()` needs the type to be `Default`; Swift's `try` → `try?` changes
  the expression's type to an optional; a swapped argument pair needs the two declared types to
  match, which this crate checks *syntactically* against the enclosing function's parameter
  annotations and cannot check at all where the language does not annotate. The crate's standard is
  **parses**, enforced by re-parsing every mutation, not **compiles** — it has no type checker and
  adding one is not in scope. This matches what the pre-existing code already did (`rust_lang`'s
  `?` rewrite was written before this lane). If the mixture needs compilable mutations, that is a new
  requirement and a large one.

- **`logic.drop_else` can leave trailing whitespace** (`} else { … }` on one line becomes `} `). It
  parses, the span is correct and both derivations agree; real agent diffs contain trailing
  whitespace too. Left as-is rather than adding a second edit to a "one mutation per diff" operator.

- **The 1000-nesting case is refused, not survived.** `parse_bounded` answers `TooDeep`,
  `ParseErrors` or `ParseBudget` depending on the grammar. That is the correct behaviour per the
  spec's refusal list, but it means the engine produces *nothing* from such a file rather than
  mutating it safely. The test asserts exactly one bounded refusal and no crash.

- **`cosmetic.edit_comment` on a Python docstring rewrites a runtime value.** `__doc__` is a real
  attribute, so a docstring rewrite is observable to `help()` and to doctest collectors. The spec
  says `edit_comment` is "always safe" and the pre-existing `python_lang::docstring` already refuses
  doctests (`>>>`). Implemented as the spec says. Flagging it because "always safe" is the spec's
  claim, not a proof.

- **`prettier` is absent on this host**, so TypeScript's cosmetic slice is measurably thinner than
  the other four. Recorded per language, never assumed away. `GAP-MUTATE-NO-PRETTIER-ON-THIS-HOST`.

## What is not proven

- **The engine has never seen a real pool.** Every number above comes from hand-written fixtures and
  a 60-record demonstration pool built from them. Refusal rates, operator yield and the
  mutated/clean balance on AgentPack or `bigcode/commitpackft` are **unmeasured**. Per
  `docs/plan-corrections.md` BLOCKING-1, AgentPack is gated and `commitpackft` is the reachable pool;
  neither was fetched in this lane.
- **`cargo test` is the only gate that ran.** There is no ledger row, no integration with
  `python/qd_data`, and no downstream consumer has read a single emitted row.
- **Operator yield per language is a property of the fixtures, not of the pool.** The coverage test
  pins that each operator *can* fire; it says nothing about how often it will on real code.
- **DevMap and GitPulse could not answer anything about this repo.** DevMap has no index;
  every GitPulse facet returned `ok: false` with `REPOSITORY_TRUST_REQUIRED`. Navigation was done
  with direct reads and ripgrep, and no claim in this document is presented as graph-confirmed.
  `GAP-MUTATE-DEVMAP-ABSENT`, `GAP-MUTATE-GITPULSE-UNTRUSTED`.
