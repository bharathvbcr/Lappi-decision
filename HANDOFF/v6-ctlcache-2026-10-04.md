## What changed (`5602617`, `tools/ft_linear_control.py` +138 / −6)

- **Two flags, both off by default and neither a recipe key.**
  - `--split-cache DIR` is the cache `real_ft_run.py --split-cache` uses.
  - `--split-cache-shards DIR` is the eval row's shard set: the directory `real_ft_run` was
    given as `--out`, which the control otherwise never sees. `split_cache.read_manifests`
    needs it.
  - Each flag without the other is refused: `--split-cache` without the shards raises
    `Refused`, and the shards without the cache is a `parser.error`.
  - `split_cache.check_dir` runs right after argv parsing, before the ledger, the verdicts or
    the split are read. That is the same point at which `real_ft_run.py:10761` checks.
- **One partial, and one owner of the runner.**
  - The rebuild is `functools.partial(split_rows_function(), <the same 15 keywords>)`. Uncached,
    it is called. With the flag, `split_cache.cached_split_rows` gets `kwargs=rebuild.keywords`,
    `rebuild=rebuild`, and the extra inputs and facts from `real_ft_run.split_rebuild_inputs`.
    This is `real_ft_run.main`'s own form (`real_ft_run.py:11134-11157`).
  - `split_rebuild_inputs` is reached by name through `split_rebuild_inputs_function()`. It
    and `split_rows_function()` share one `_runner()` import-and-refuse.
  - A runner without `split_rebuild_inputs` is refused, never replaced by a local list.
- **An early shard-set check** (`check_shard_set`). This refusal was not in the brief; the lead
  should rule on it (see For the lead).
  - Before the rebuild, the shard set's `data/pool/train.json` must name the eval row's
    `protocol.data_snapshot_hash`. An unreadable manifest is refused too.
  - The pairing is sound [V, code read]:
    - `real_ft_run.corpus_facts` refuses a train manifest whose hash is not the shard header's
      (`real_ft_run.py:4520-4525`);
    - `_protocol` writes the header's hash into every eval row (`:2466`);
    - the v5 shard row `c3bd0374` (`ledger/mac-v5-shards-2026-10-03.jsonl`) names
      `cb4b7d3a…`, the same hash as `phase4-v5r-2026-10-03/data/pool/train.json`.
  - Why: with another build's manifests, every call is a miss whose rows fail the cache's own
    manifest check and are never stored. That costs the full rebuild on every call, and only a
    metric says so.
  - Cost: 0.8 s and 1.1 GiB peak to parse v5's 270 MB train.json [V, a timing run under
    `mac_heavy` at 11:31Z].
- **The metric.**
  - The letter row carries `split_cache`. The option row carries
    `linear_option_control.split_cache`.
  - Each is the `TriState` that `cached_split_rows` returns, in `real_ft_run`'s form: a `Ran`
    whose value is `hit`, `miss` or `corrupt`, whose detail starts `key <sha256>; `, and whose
    `passed` is False on `corrupt` or "not stored". It is a `NotRun` when no key could be
    computed.
  - Without the flag, no row carries it.
  - **The option row's name differs from the brief's "a `split_cache` metric"** [V].
    `test_option_control.py:404-406`
    (`test_the_option_row_changes_nothing_the_ledger_joins_or_promotion_reads`) requires every
    option-row key except `code_that_ran` to start `linear_option_control.` or
    `paired_margin_vs_linear_option.`. The lane followed the test. See For the lead.
- **Unchanged.**
  - The control's own rule-3 check (`ft_linear_control.py`, after the split) still runs on
    cached rows, after `split_cache`'s own two-sided check.
  - The `RunRecorder` still opens after the split. A rebuild that crashes writes no row, as
    before.
  - The exit codes are as before.

## The box invocation (the exact shape a box script passes)

**Preconditions:**
1. **A checkout with this branch** (or its merge), with `14f9329` under it. `03d335d` has it, so
   this branch does: `exclusions.corpus_matches` no longer refuses `max_pairs=0` where it bounds
   nothing (GAP-V5-CONTROL-MAX-PAIRS-KEY-MISMATCH-2026-10-04).
   - The checkout's gitignored `data/pool` must hold the corpora that the v5 rebuild resolves
     under REPO. That is true with or without the cache.
   - Its tree must not change during the session, because the key hashes every `*.py` under
     `python/` and `tools/`.
2. **One `QD_PREP_BIN` and one Python environment for every call.** Both are in the key, so
   every call then shares one entry.
3. **A dedicated directory for the controls,** for example `/home/ubuntu/split-cache-ctl`. Its
   parent must exist; the tool creates it 0700 when it is absent.
   - **Do not share `real_ft_run`'s directory.** Under v5's flags the control passes
     `max_pairs=0` (`ft_linear_control.py`, "Unread by the rebuild when it bounds nothing") and
     `real_ft_run` passes its default of 400.
   - The rows are byte-identical (above), but the keys differ. With `MAX_ENTRIES` = 2, two
     tools and one code revision in one directory evict each other.
   - Disk: 1.7 GB per entry, at most 3.4 GB.

**Per seed** (`$V5_DATA` is V5_SPLIT's `--out`, which `v5_split_check` sets;
`v5_common.sh:292`):
```bash
SC=(--split-cache /home/ubuntu/split-cache-ctl --split-cache-shards "$V5_DATA")
nice -n 10 "$PY" -u tools/ft_linear_control.py --ledger "$V5R_LEDGER" \
  --verdicts "$V5R_OUT/verdicts-s$SEED.jsonl" "${V5_CTL_SPLIT[@]}" "${SC[@]}"
nice -n 10 "$PY" -u tools/ft_linear_control.py --ledger "$V5R_LEDGER" \
  --verdicts "$V5R_OUT/verdicts-s$SEED.jsonl" "${V5_CTL_SPLIT[@]}" "${SC[@]}" --option-control
```
- **Through `controls_block`.** `controls_block` (pinned, `idle_common.sh:100-113`) passes
  `"${CTL_SPLIT[@]}"` to both calls. A rerun wrapper can therefore set
  `CTL_SPLIT=("${V5_CTL_SPLIT[@]}" "${SC[@]}")` and leave `controls_block` unedited, as
  `v5_controls` sets it (`v5_common.sh:931-938`).
- **Order.** Run the first call alone, to completion: it is the MISS that stores the entry.
  Every later call, letter or option, any seed, is a hit.
  - Simultaneous first calls are safe (the race is tested in `test_split_cache.py`). Each one
    would still pay the rebuild.
  - **Their memory is a hazard too, not just CPU** [V]. The MISS peaked at 26.8 GiB resident
    in one process (`measure-miss.log`). A hit peaks at 3.8 GiB.
    `box_q_v5traj.sh:93-98` runs each seed's `v5_controls` concurrently. A rerun that copies
    that pattern before any entry exists would start N rebuilds at once, about N × 27 GiB.
    Run the MISS alone; the hits may then run side by side.
  - Every call prints a `split cache:` line, and every row carries the metric, so a call that
    missed when it should have hit is visible on its row.
