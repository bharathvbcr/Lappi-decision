The contract a trainer uses: `plan.positions()` are distinct and ascending. Pass them to
`PendingStep::hidden(positions)` for the input rows, and pass `HiddenGrad { positions, rows }`
to `train_backward_into(dh = (positions, [n, H]))` as they are. A query that is also a line
start is one position, and its gradient is the sum of both paths: that is the pre-sum tessl's
`check_scatter_rows` requires. `loss` is the unweighted mean over the 2K pointer decisions,
which is what `span_log` records. Gradients are of `span_weight * loss`, and weight gradients
are added into the bank, as torch accumulates `.grad`.

## How the fixtures stay small

The `[H, H]` weights are not stored. A SplitMix64 counter generator produces them, both sides
implement it, and the values are exact in f32. Each manifest pins the sha256 of the bytes torch
used, and the Rust test checks that digest before anything else.

dW at H = 2048 is encoded through `dq`, with K = 1. The oracle asserts that torch's dW is
bit-equal to `outer(dq, h_query)`. The Rust test rebuilds all H² elements and re-proves the
digest. Both are lossless, and neither is a sample. The float64 arm (`ref64_*.npy`) is about
1.2 MB of the 2.7 MB. If the lead wants it smaller, the manifest scalars `torch_f32_vs_f64` can
replace it, but gate B would be lost.

## What the Rust head does not reproduce

- **The campaign's bf16 tower.** `accumulate_span` casts bf16 hidden states to f32 and rounds
  the hidden-state gradient back to bf16. tessl's final hidden is f32 and so is `dh`. The
  oracle and this head are the fp32-hidden path, Fable's "fp32-master analogue" (Q1 row 9).
- **The training padding.** `heads.py` pads to the batch's widest candidate set with `-inf`.
  This head returns the serving layout (`serving_scores`), with no padding. The test
  re-pads the Rust output and requires torch's padded columns to be `-inf`.
- **`reduction="sum"`.** `accumulate_span` never uses it, so it is not implemented.
- **Gold as token positions.** The plan takes gold as ordinals (`SpanGold`). Mapping token →
  ordinal belongs to `plan_span_batch`'s port (Fable row 14, the supervision lane). The
  fixtures check that the ordinal names the gold token's line.
