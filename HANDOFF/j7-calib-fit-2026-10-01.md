## What it does

- **Where it lives.** `qd-calib-fit` sits in `qd-runtime` beside `qd-margin-probe`.
  - There was no reason to move it. It builds the table as `qd_runtime::calibration::CalibrationTable` and reads every probability through `calibrate`.
- **What it fits.** Per `{kind}:{rows}` entry it computes three things:
  - `temperature`: `fit_temperature`'s ternary search.
  - `noul_margin`: `fit_noul_margin` over the calibrated margins.
  - `conformal_quantile`: `1 - q̂`, where `q̂` is `split_conformal_threshold` on the calibrated probabilities, converted only through `probability_cutoff_from_nonconformity`.
- **Outputs.** `table.json` is `serde_json::to_vec(&table)`, so the file's sha256 is `CalibrationTable::hash()` (**verified**). The binary also writes `report.json` and a per-row `rows.jsonl`.
- **Population is a flag, never a policy.**
  - `--population all` fits and scores in-sample.
  - `--population two-fold --split-key K` uses the margin probe's split: fold a iff `sha256(K‖0x00‖row_id)[0]` is even. It writes **both** fold tables and no pooled table, and scores every row with the other fold's parameters.
  - The report states the population and its counts. A row whose other fold fitted nothing is counted in `n_not_scored`, never inside a rate.
  - **Gold-noul rows are inside every fit.** A row whose gold is the noul row is fitted as that class and counted in `gold_noul`. The margin probe excluded such rows for its own purpose; this tool does not.
  - This matters for J4: CLINC's out-of-scope rows are gold-noul. Excluding them would be a population choice, and that choice is the human's.
- **ECE metrics keep `ece_gate`'s own shape.** `passed` means `value <= 0.05`; below 100 rows the state is `not_run`.
  - Every other metric carries `passed=True`.
  - These are metrics on a quick row, not gates. The detail string says "report-only".
- **Round trip (verified, `calib_fit_roundtrip.rs`).** The file is deserialised into the runtime's type, passes `validate`, is accepted by `Runtime::with_backend`, and is used by `Runtime::answer`:
  - A fitted shape answers.
  - An unfitted shape refuses with `calibration_entry_missing`.
  - So does span.
  - No serve-time file reader exists; `qd serve` builds the reference table in code.

## Decisions that need the human's eye

1. **`float_roundtrip` enabled on serde_json for `qd-runtime`.**
   - It adds no crate: the feature is `[]` in serde_json's manifest, and `Cargo.lock` is unchanged.
   - Why: the default parser read the fitted cutoff `0.9984102332289755` back one ulp off (`…b9d0` read as `…b9d1`). A table loaded from the file was then not the fitted table, and its `hash()` was not the file's sha256.
   - Pre-fix, 3 of the 4 round-trip tests fail (**verified**).
   - Features unify across a workspace build. `cargo test --workspace --exclude qd-metal` passes (**verified**).
   - `qd-metal` compiles under it: `cargo check --all-targets` and `cargo test --no-run` both succeed (**verified**). Its tests were not run, because they use the GPU.
2. **The table's sha256 is a metric, not a recipe key.**
   - The recipe is hashed into `Protocol.recipe_hash` before the binary runs, and the table is the binary's output.
   - The binding re-reads the written file and checks its hash against the report.
3. **One model per row.** The binding refuses eval rows that differ in data, tokenizer, backbone or seed, because `Protocol` carries one seed. So J4 is three fits, not one pooled fit.
4. **`noul_margin` is degenerate on accurate entries (measured).**
   - When an entry's accuracy exceeds the target precision, `fit_noul_margin` returns the **minimum observed margin**. That is an unstable order statistic.
   - On phase-3 s0 (99.79% correct), fold a fitted 0.3771 and fold b fitted 0.01485 (row `7026786b`).
   - The definition is `calibration_fit.py`'s, ported exactly. Whether it is the right rule is the human's call.

## What is open (gap ids)

- `GAP-CALIB-SPAN-NOT-FITTABLE-FROM-VERDICTS` (human): span verdicts carry no distribution, so every fitted table has `span: null`. Installing one disables span answers.
- `GAP-RT-CALIBRATION-HASH-PIN-BINDS-THE-BACKEND-NOT-THE-LOADED-TABLE` (human):
  - `check_hashes` compares the pin with the backend's declared hash, not with the loaded table's.
  - Measured: a fitted table's own hash is refused with `hash_mismatch`, and the reference hash is answered.
  - Not fixed here: it is a security-adjacent contract change.
- `GAP-RT-CALIBRATION-NOT-FITTED`: still open. The fitter exists; it has not been run on J4, and there is no serve-time loader.
- `GAP-J7-CALIB-DEVMAP-NO-STORE-IN-THIS-WORKTREE` and `GAP-J7-CALIB-GITPULSE-UNTRUSTED-AND-NO-LISTAGENTS`.
- Follow-up, no gap id: `qd_margin_probe.rs` keeps its own `fit_noul_margin`, split and reader. It could delegate to `qd_runtime::calibration_fit`; that was left alone to keep this change in one concern.
