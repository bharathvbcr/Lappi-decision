## Findings

### 1. The two lanes did not mean the same thing by "blank" — FIXED

`GAP-XLANG-WHITESPACE-NOTION-SPLIT`.

Python asks `str.strip()`, which strips what `str.isspace()` accepts: **29 codepoints**. Rust asked
`str::trim()` / `char::is_whitespace()`, the Unicode `White_Space` property: **25**. The difference
is exactly **U+001C, U+001D, U+001E, U+001F**. Four Rust sites asked the narrower question, and the
Python lane was missing one check outright.

Measured before the fix, each through both real lanes:

| Payload | Rust | Python |
| --- | --- | --- |
| context of `\x1c` | **rendered** | `EmptyContextRefusal` |
| option `"\x1c"` | **accepted** | `EmptyOptionRefusal` |
| option `"\x1cnoul"` | **accepted as an ordinary option** | `ReservedOptionNameRefusal` |
| slot name `"\x1c"` | **accepted** | refused |
| task `""`, `" "`, `"\xa0"`, `"\x1c"` | `empty_task` | **all rendered** |

The context row is the worst: the runtime produced a confident letter from a context with no
content, which is the one thing `docs/hardening.md` §3's rule exists to prevent. The `"\x1cnoul"`
row is a seventeenth apparent option whose text *is* the reserved abstain label.

Two false claims produced this and neither was executable:

- `Context::non_whitespace_len`'s doc comment said the Unicode notion "is what
  `python/qd_data/render.py` uses (`str.strip()`), so a context of nothing but U+00A0 is refused by
  both lanes rather than by one." True of the one character it named, false of the class.
- `test_qd_data_wire_agreement.py` listed `empty_task` in `NO_QD_DATA_COUNTERPART` as one of "the
  two checks the builder makes **structurally impossible** rather than refusing." It was not
  impossible, it was unchecked.

The pre-existing cross-language test
`both_lanes_refuse_the_same_payloads_and_name_the_context_checks_identically` **passed the whole
time**, because its negative set never sent a separator-only payload.

**Fix — one canonical owner.** `qd_runtime::is_wire_whitespace`, with `wire_trim` and `is_blank`
beside it, at the crate root because it governs four modules. All five Rust call sites now use it
(`context.rs` `non_whitespace_len` and its non-UTF-8 byte branch, `wire.rs` task / option-empty /
reserved-label, `schema.rs` `slot_name_fault`). The byte branch was separately inconsistent with its
own sibling — it used `u8::is_ascii_whitespace`, which omits U+000B — and is now the ASCII range of
the same predicate. On the Python side, `qd_data.errors.EmptyTaskRefusal` (`check = "empty_task"`,
one-to-one with the runtime identifier so it needs no `KNOWN_VOCABULARY_DIFFERENCES` entry) is
raised from `Request.__post_init__`, and `empty_task` is out of `NO_QD_DATA_COUNTERPART`.

**Pinned executably, not in prose.** `wire_context_crosslang.rs` now reads the **real**
`str.isspace()` over the whole codepoint range and the **real** `str.strip()` over a table of
adversarial strings, at test time. Because that file is guarded by `doc_or_skip!` and returns early
without `.venv`, a second test pins the 29-codepoint set as a literal that **always** runs — a rule
checked only when a directory exists is not checked.

Pre-fix failure, quoted:

```
the two lanes disagree about what whitespace is, so they refuse different contexts.
  Python strips but Rust keeps (Rust renders what Python refuses): ["U+001C", "U+001D", "U+001E", "U+001F"]
  Rust strips but Python keeps (Rust refuses what Python renders): []
```

```
U+001C alone: the Python lane refuses this context as `context_empty`; this lane answered
Ok(RenderedPrompt { prefix: "...<|qd_context_begin|>\n\\u001c\n<|qd_context_end|>\n", ... })
```

### 2. A permutation that is not a permutation was applied in part — FIXED

`render::slot_suffix` mapped the second pass's index list with
`order.iter().filter_map(|i| options.get(*i))`. `filter_map` **drops** what it cannot resolve, so an
index outside the option list silently removed an option instead of refusing. Measured against
unmodified code, on a 3-option slot:

| permutation | rendered rows |
| --- | --- |
| `[5,6,7]` | **1 row — `Z. noul` only** |
| `[0,0,0]` | `A. alpha`, `B. alpha`, `C. alpha` |
| `[0]` | 2 rows |
| `[0,1,2,0,1]` | 6 rows |
| `[usize::MAX]` | 1 row |

Every case leaves `SlotRender::rows` disagreeing with `SlotSpec::answer_rows()`, which is the row
count `answer::SlotPlan::rows` hands the backend — so the decode is taken over one shape while
`perm.get(cal2.top)` maps the winner back through another. With the all-out-of-range list the
contract's step-4 agreement check runs against a prompt with nothing to agree about and abstains on
everything, quietly.

**Not reachable from the wire today**: the only caller is `answer::answer_generic`, which passes
`second_pass_permutation` — a Sattolo cycle, always well formed. That is an argument about today's
one caller, not a property of the function.

**Fix**: `check_permutation` in `render.rs`, called from the Choice arm of `slot_suffix`, so both
`render` (which passes `&[]`) and `permuted_slot_suffix` flow through one check. The map is now
total and its output length is verified rather than argued.

Pre-fix failure, quoted:

```
every index out of range: [5, 6, 7] is not a permutation of 0..3, and it was applied anyway.
The slot rendered 1 rows where an intact one has 4, and the rows are [Noul]
```

## Attacked and held — no defect found

These are results, not gaps in the testing.

- **Every byte cap is exact.** At-cap accepted, cap+1 refused, each with its own named refusal:
  context 131072, question 4096, task 256, option 512, slot name 256, slots 32, options 2..16, bins
  2..16. No off-by-one anywhere.
- **The payload cap.** Exactly `MAX_PAYLOAD_BYTES` is read; `+1` is `payload_over_cap`. Correct `>`.
- **The 16+1 letter budget.** 16 options yields 17 rows. The SETTLED reading holds.
- **Malformed UTF-8 in the context.** Lone surrogates (CESU-8), overlong `C0 AF` and `C0 80`, bare
  continuations, truncated sequences and `0xFF` are all `context_not_utf8`. No CESU-8 or
  Modified-UTF-8 laxness.
- **Embedded NUL, bidi controls, U+2028/29, and a forged `<|qd_context_end|>` marker** are escaped
  as data, never structural. The `<|` rule holds.
- **`HashExpectation` unknown fields.** `deny_unknown_fields` is present and works — a pinned digest
  under a misspelled key is `malformed_request`, not a silently unpinned request. This was a
  hypothesis; it was wrong.
- **Unicode case folding of the reserved label.** Rust uses `eq_ignore_ascii_case` and Python uses
  `casefold()`. A brute-force sweep of all 0x110000 codepoints found **no** character that casefolds
  into `n`/`o`/`u`/`l` differently from `lower()`, so the two agree for this label.
- **Duplicate JSON keys.** Both `serde_json` and Python's `json` take the last value; they agree.
- **`qd-mutate`'s no-op backstop is real.** `Refusal::NoTextualChange` (`generate.rs:477-485`) plus
  `diffspan.rs:29-31` mean a byte-identical edit **cannot** be emitted with a mutation label, and
  eleven of the seventeen operators additionally decline no-ops at candidate time. The span label is
  cross-checked by two independent derivations that must agree. This premise holds; do not spend
  budget re-deriving it.

## Open, deliberately not fixed

1. **`qd-mutate`'s class label is intent, not fact.** `class: op.class()` (`generate.rs:557`) is a
   constant chosen from the operator enum before any edit runs. So a *semantically* inert edit still
   ships as `logic` — `logic.swap_args` on a commutative callee (`ops.rs:743`),
   `logic.change_constant` on a literal in dead code (`ops.rs:877`) — and `cosmetic.rename_local`,
   `cosmetic.edit_comment` and `cosmetic.reorder_imports` carry a behaviour-preserving label with no
   post-edit verification, since `verified_by_canonical_form()` (`ops.rs:189`) covers only
   `reformat` and `wrap_line`. Note `cosmetic.edit_comment` rewrites Python **docstrings**, which are
   runtime-visible values. This is not a bug with a fix: deciding semantic equivalence is
   undecidable in general. It is a **bound on what "labels by construction" means** — syntactic, not
   semantic — and the trainer cannot detect it, because `before` and `operator` never cross into
   `mutate_adapter.py`; it sees only `after` + `class` + `span`.
2. **`hunk_constrained` means two things.** On the mutated path (`generate.rs:465`) the intersection
   rule is genuinely enforced; on the clean path (`generate.rs:296`) the same field is set from
   `record.hunks.is_some()` with **no** placement rule applied, because a clean row has no edit to
   place. The field's doc and `pool.rs` both define it as the presence check, so code and document
   agree — this is a conflation, not a defect, and the field crosses into training
   (`mutate_adapter.py:214`). Changing documented wire semantics is the owner's call, not a stress
   lane's drive-by.
3. **`Context::line_starts()` disagrees with itself and with Python on the empty context.** Rust
   returns `[0]` (length 1) while `Context::line_count()` special-cases empty to `0`, and Python's
   `byte_context.line_starts(b"")` returns `()`. Unreachable today — an empty context is refused by
   `render` before any span is taken — but `line_starts` is `pub` and documented as "the definition
   of line for the whole system".
4. **The two unescapers accept different alphabets.** `render::unescape` accepts uppercase hex and,
   via `u32::from_str_radix`, a **leading `+`** — `\u+041` unescapes to `A` — where Python demands
   exactly four lowercase hex digits inside `HEX_ESCAPED`. Both invert their own escaper exactly, so
   no round trip is affected. Recorded as measured, not fixed.
5. **`no_textual_change` has no alarm.** `Totals` (`manifest.rs:133-153`) has dedicated fields for
   `span_disagreements`, `outside_hunk` and `mutation_did_not_parse` but not for this one, and
   `main.rs:157-163` warns only on span disagreements. If `logic.negate_condition` (`ops.rs:706`) or
   `logic.swallow_error` (`ops.rs:852`) — the two operators with no candidate-time no-op guard —
   ever started round-tripping, the mixture would degrade silently.
