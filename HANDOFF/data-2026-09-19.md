### Two defects found, each with its pre-fix failure count measured

**1. The renderer let eight characters forge an option line.** `escape_inline` escaped only `\n`,
`\r` and `\t`. `str.splitlines()` — and several tokenizer preprocessors — also break on U+000B,
U+000C, U+001C, U+001D, U+001E, U+0085, U+2028 and U+2029, and on a bare `\r`. An option containing
one rendered as **two apparent option lines**, which is the "17th apparent option" `hardening.md` §3
forbids, while `prompt.count("\n")` reported the format intact. The same characters in the *context*
made `splitlines()` and `split("\n")` disagree on the line count, so two derivations of a span line
number point at different lines — §1's systematic off-by-one, arriving through the data instead of
through the mutator.

Measured: reverting only the escape change and re-running `test_render.py` gives
**10 failures** (`test_inline_escape_emits_exactly_one_line`,
`test_block_escape_makes_line_counting_unambiguous`, and 8 parametrizations of
`test_an_option_containing_a_line_break_cannot_become_a_seventeenth_option`). With the fix: 47/47.

Fix: those nine characters plus U+0000 are escaped as `\uXXXX` in **both** modes. Block mode still
emits real `\n`, so the newline-count invariant is untouched. `unescape` is still an exact inverse
and refuses a `\u` escape for any codepoint outside the set. `RenderCaps.max_rendered_bytes` rose
from 393,216 to 802,816 because worst-case escape growth is now 6x, not 2x — the cap check exists so
a legal context can never be refused by arithmetic, and leaving it at 2x would have made a legal
131 KB context of U+000B spuriously refusable.

**2. The first dedupe deleted two thirds of the mixture and reported clean.** One
`bigcode/commitpackft` row becomes three examples (commit intent, language id, change scope) from
the same file. Comparing *examples* makes those exact duplicates of one another. Measured on a
24-row synthetic corpus: **210 rows in, 90 out, 120 dropped, status `Ran(passed=True)`.** A real run
would have trained one family per source row and called the dedupe clean.

Fix: dedupe operates on **content units** — `(identity_key, digest(dedupe_text))` — so every example
built from one piece of content is one node, and a dropped unit takes all its examples with it. Same
corpus after: 210 rows / 90 units in, 210 out, 0 dropped. `test_dedupe_split.py::
test_the_three_families_of_one_source_row_are_one_content_unit` fails against the pre-fix code.

### Three design decisions that changed a default, with the measurement behind each

- **Dedupe drops only *cross-repo* duplicates.** `hardening.md` §2 names the hazard precisely:
  *"vendored trees, forks and copied files put the same code in two repos"* — the case a repo-level
  split cannot separate. Two near-identical rows inside one repo always land on the same side, so
  dropping them removes data without removing a leak; for `squad_v2`, several questions share one
  passage and sit at Jaccard ≈ 0.85 by construction, so within-repo dropping would have removed
  almost all of it. Within-repo pairs are **counted and reported** (`n_within_repo_pairs`), never
  deleted.
- **The LSH banding objective is recall-weighted, not balanced.** A false positive costs one exact
  Jaccard comparison, because every candidate is exactly confirmed before it is called a duplicate —
  so precision is exact whatever the banding does. A false negative is undetected contamination.
  Measured at `num_perm=128, threshold=0.8`: balanced weights pick `b=9, r=13`, whose probability of
  even *proposing* a genuine 0.85-Jaccard pair is **0.686**. The chosen weights (0.05 / 0.95) pick
  `b=16, r=8`: **0.947** at the threshold, 0.994 at 0.85, 0.9999 at 0.9, at a 0.061 candidate rate at
  0.5. `test_minhash.py::test_balanced_weights_would_have_missed_a_third_of_real_duplicates` pins it.
- **`DataConfig` gained `val_fraction` (0.05).** `SPLITS` has three entries and the config had one
  fraction, leaving "the rest" implicit — which is how a three-way split quietly becomes a two-way
  one. Train/val/heldout is now 0.90/0.05/0.05 and the three must sum to < 1.0 or construction
  fails, because a natural held-out set of size zero passes every leakage check vacuously.

## Injection attacks: defended vs not

Every row of `hardening.md` §3 is a test in `test_render.py`. The defence is two invariants, property-
tested with hypothesis over arbitrary text rather than a blocklist of known token names — a blocklist
goes stale the moment the tokenizer gains a token, and goes stale silently.

| Attack | Status | Test |
| --- | --- | --- |
| Context contains `Answer: B` | **Defended.** Marker counts and the letter→value map are byte-identical to a clean render | `test_injected_context_cannot_forge_structure[answer_decoy]`, `test_injected_context_does_not_shift_the_letter_map` |
| Context lists the literal option letters | **Defended** | `…[option_letter_list]` |
| Context contains the literal `noul` token | **Defended.** Option block unchanged | `…[literal_noul]` |
| Context contains `<\|im_start\|>`, `<\|endoftext\|>` | **Defended.** Rendered as text; `<\|` cannot survive escaping | `…[chat_special_tokens]`, `…[endoftext]` |
| Context contains the question delimiters | **Defended.** No early termination; the context region round-trips to the exact arriving bytes | `…[question_delimiter]`, `…[context_terminator]`, `…[slot_forge]`, `…[begin_marker]`, `…[options_block]` |
| Context all whitespace / empty | **Defended.** `EmptyContextRefusal`, incl. U+00A0 | `test_empty_and_whitespace_context_are_refused_not_answered` |
| Duplicate options | **Defended.** `DuplicateOptionRefusal` at construction | `test_duplicate_options_are_refused` |
| Options with newlines or the delimiter → 17th apparent option | **Defended after the fix above**, across all 10 line-break characters | `test_an_option_containing_a_line_break_cannot_become_a_seventeenth_option` |
| Option longer than the cap | **Defended.** `OptionTooLongRefusal`, refused not truncated | `test_option_over_the_cap_is_refused_not_truncated` |
| Context longer than the cap | **Defended.** `ContextTooLargeRefusal` | `test_context_over_the_cap_is_refused_not_truncated` |
| **Bidi overrides (U+202A–U+202E, U+2066–U+2069)** | **NOT defended — deliberate.** A "Trojan Source" reordering makes text render differently from how it tokenizes. Not escaped, because escaping it would corrupt legitimate RTL content, and the model reads tokens rather than glyphs. **Human call — `GAP-DATA-RENDER-BIDI-UNESCAPED`** | none |

Also proven: the training renderer and a serving-shaped call produce **byte-identical** prompts
(`test_training_and_serving_render_byte_identically`, the test `render.py` names in its own
docstring), and — the stronger form — every *shuffled* training prompt is reachable from a wire
request (`test_every_training_prompt_shape_is_reachable_from_the_wire`), so no shape exists in
training that the runtime cannot emit. `test_mixture.py::
test_every_rewritten_row_renders_and_round_trips_through_the_wire` repeats it for every row the
pipeline actually produces, not just a hand-built one.

Every refusal is typed and **structurally distinguishable from `noul`**:
`test_every_refusal_payload_is_structurally_distinguishable_from_noul` sweeps **every**
`QdRefusal` subclass in the package (19 of them, discovered by walking `__subclasses__` after
importing every defining module, and constructed from their signatures so a new one with its own
constructor is still swept), and asserts each payload is a refusal, is not a `noul` payload, carries
no `value`/`noul`/`score`/`conformal_set`/`degraded` attribute, and sets a non-default `check` id.

## Held-out enforcement

`qd_train/data_access.py` is the only door into training data. `open_training_data` runs four
independent layers and raises `HeldOutViolation` — never returns empty, never returns `noul`:

1. **Configured roots**, compared on resolved absolute paths, so `pool/../heldout/x` and a symlink
   into the held-out tree are both caught, and the check fires on a path that does not exist yet.
2. **Path markers**, segment-exact (`heldout`, `held_out`, `held-out`, case-insensitive) so a rename
   out of `data/` does not launder it — and `withheld_outputs` is *not* refused, because a substring
   check there would starve the trainer while looking fine.
3. **The manifest's own declaration.** A held-out manifest copied to a clean path is still refused.
4. **The family holdout.** A shard declaring `train` that carries a held-out family identifier, or
   that records a different holdout than this run configures, is refused (rule 2: a holdout may not
   be shrunk to make a gate pass).

`test_data_access.py::test_pointing_the_trainer_at_a_held_out_manifest_raises` is the test
`hardening.md` §2 asks for by name. Removing any layer is a refused change (rule 3).

A fifth refusal, not a holdout but the same shape: training on a snapshot whose pipeline status is
`NotRun` (for example a dedupe pass that hit its candidate bound) is refused unless the caller passes
`allow_not_run_snapshot=True`, and the reason travels into the handle either way.

## `data_snapshot_hash`

`build_manifests` → one `Manifest` per split → `data_snapshot_hash(manifests)`. Covers the config
fingerprint, the admitted roster, the refusal report, the held-out family list, and every row's
content hash with its split. Excludes wall clock, host, row order, row ids and paths.

Proven in `test_manifest.py`: same inputs → same hash; order-independent; unaffected by provenance;
**moves** for a change to seed, `train_fraction`, `dedupe_threshold`, `shingle_size`,
`held_out_families`, a licence override, or one added row; refuses a hash over a subset of splits or
over zero manifests; and the result is accepted by `qd_train.ledger.Protocol`.

Order-independence needed two fixes found by that test: CLINC identity was keyed on the enumeration
index (a pull at a different offset renamed every row), and the commit-intent decoy was drawn from
the arrival-ordered message list. Both are now keyed on upstream identity.

A manifest re-derives its hash on read and refuses an edited file. A `NotRun` manifest refuses to be
written without `allow_not_run=True`, and the reason is in the file either way.

```python
from qd_data.config import DataConfig

from qd_data.split import split

config = DataConfig()
raw = [parse_commitpackft(r, index=i) for i, r in enumerate(
    fetch_rows("bigcode/commitpackft", config_name="python", split_name="train", limit=300))]
mixture = build_mixture({"bigcode/commitpackft": raw}, config=config,
                        capped_sources=["bigcode/commitpackft"])   # 300 of 702k -> NotRun, correctly
report = dedupe(list(mixture.rows), config=config)
manifests = build_manifests(config=config, mixture=mixture,
                            dedupe_report=report, split_report=split(report, config=config))
print(data_snapshot_hash(manifests), manifests["train"].status.to_json())
```

Note that this deliberately reports `not_run`: a 300-row sample of a 702k-row pool is a capped
sample, and the mixture says so rather than presenting it as coverage.
