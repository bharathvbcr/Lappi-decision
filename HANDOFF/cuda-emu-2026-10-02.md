# L-cuda-emu — handoff, 2026-10-02

Goal: a test-time CPU emulator that **executes** the CUDA-C NVRTC sources of
`ojas-qwen35-cuda` with the host `clang++`, so index, barrier and reduction-order bugs are caught
before a GH200 run. **It is not a GPU run and is never reported as one.** Device tests stay NOT
RUN. Every emulator driver prints `cuda_emu: CPU emulation of CUDA-C on the host C++ compiler. NOT
a GPU run.` as its first line, and `Outputs::provenance()` carries it.

### How it works

`Program::run` rewrites only `extern __shared__ T x[];` (into a reference to the launch's dynamic
shared memory) and a `static` next to `__shared__`. Both rewrites happen on tokens, so comments
are untouched and line numbers survive. It then generates a driver that calls the entry with typed
arguments, compiles with `-std=c++20 -O1 -ffp-contract=off -fno-strict-aliasing`, runs it in a
temp directory under `CARGO_TARGET_TMPDIR`, and reads every buffer back. Compilation and the run
are bounded: 300 s to compile, a per-launch watchdog inside the driver (60 s by default, 300 s
under a sanitizer), and a host-side kill backstop. A missing compiler is `ErrorKind::CompilerMissing`,
**never a skip**.

Inside the driver, blocks run one at a time, so `__shared__` can be a `static`. Each CUDA thread
is a `std::thread`, and thread-local `threadIdx`/`blockIdx`/`blockDim`/`gridDim` follow the brief.

| bug class | how it surfaces | ErrorKind |
| --- | --- | --- |
| divergent `__syncthreads` (other line or call count) | checked when the barrier completes | `Diagnostic` |
| shuffle reads an exited / absent (partial warp) / unmasked lane | checked when the warp group completes | `Diagnostic` |
| lanes waiting at different collectives, or warp op vs barrier | checked at the post | `Diagnostic` |
| a wait cycle no single check names | every live thread blocked, nothing can complete | `Deadlock` |
| spin-wait that never ends | per-launch watchdog, with a dump of who waits where | `Timeout` |
| out-of-bounds **write** | 256 guard bytes around every buffer and the dynamic smem | `OutOfBounds` |
| out-of-bounds **read**, int32 index overflow | `Sanitizer::Address` (ASan+UBSan) | `Memory` |
| missing `__syncthreads` / `__syncwarp` | `Sanitizer::Thread` | `Race` |
| output element nothing writes | outputs pre-filled 0xFF (NaN) | value check |
| shared memory read before write | static and dynamic smem filled 0xFF before **every** block | value check |
| overlapping writes across blocks / inter-block race | `run_order_invariant` runs forward, reverse and shuffled orders | `OrderDependent` |
| reduction-order change | `assert_bitwise_eq_f32` against a host mirror in the kernel's order | panic |

`assert_bitwise_eq_f32` **refuses** a kernel that calls a transcendental, that is compiled without
`--fmad=false`, or that is compiled with a fast-math option. Those kernels go through
`assert_close_ulps_f32`.

### Departures from the brief (both measured, both in the AUDIT note)

1. **No `std::barrier`.** On clang 18 + libc++ it makes TSan report races in a correctly barriered
   program (3 of 3 runs; libstdc++ 0 of 3). The block rendezvous is a mutex plus one condition
   variable per thread. A returning thread leaves every rendezvous, which matches the brief's
   `arrive_and_drop`.
2. **Warp exchange through the block rendezvous**, not a separate slot array and warp barrier.
   Under TSan the rendezvous is hidden, and only CUDA's guaranteed orderings are reported:
   `__syncthreads*`, `__syncwarp`, and nothing for shuffles or votes. With it visible, a missing
   `__syncthreads` went unreported.

const NVRTC_OPTIONS: &[&str] = &["--fmad=false" /* , ...the crate's own... */];

fn rmsnorm_kernel_matches_the_host_mirror_bitwise() {
    let src = concat!(env!("CARGO_MANIFEST_DIR"), "/src/rmsnorm.rs");
    let k = Kernel::from_rust_const(src, "<THE_NVRTC_SOURCE_CONST>")
        .unwrap_or_else(|e| panic!("{e}"))
        .with_nvrtc_options(NVRTC_OPTIONS);

`include_str!`, or a `concat!` of string literals. For anything else (e.g. `format!`), pass the
crate's public constant with `Kernel::new`. Compile errors then cite the `.rs` file and line.
Kernels that call `expf`/`tanhf`/`rsqrtf` (e.g. SiLU gates) compare with
`assert_close_ulps_f32`. Whatever the emulator says, report it as **CPU emulation**, quoting
`Outputs::provenance()`, never as a device result.
