## What this lane was for

`docs/lappi.md` puts rung 0 at the bottom of the ladder: a byte-level decider trained from
scratch, no pretrained backbone, no Hugging Face terms on the critical path. Everything
below existed as pieces; none of it could take a gradient step. It now can.

## The defect that was blocking it, and its class

`python/qd_train/byte_batch.py` declares itself torch-free — *"so the index arithmetic runs
in CI"* — and then imported `RESERVED_NOUL_ROWS` from `heads.py`, which imports torch at
module scope. In the repo venv (which deliberately has no torch) the module could not be
imported at all.

That was the **second** symptom of one cause, not a one-off. `calibration_fit.py` had hit
the same wall earlier and worked around it by restating all six schema constants with its
own Rust-pin test. So the constants were defined twice, and a third consumer broke.

**Fixed at the class:** `python/qd_train/schema_mirror.py` is now the single Python owner of
`MAX_OPTIONS`, `MIN_OPTIONS`, `RESERVED_NOUL_ROWS`, `CHOICE`, `SCORE`, `SPAN`. It imports
nothing but `typing`, so anything may depend on it. `heads.py` and `calibration_fit.py`
re-export from it, which kept every existing import site working.

The guard is `python/tests/test_schema_mirror.py`, and it is measured rather than asserted:
a subprocess installs a `sys.meta_path` finder that refuses `torch`, imports **every** module
under `qd_train`, `qd_data` and `qd_wire`, and requires the set that fails to equal the
declared `TORCH_GATED` exactly. Both directions — a new leak fails, and so does a stale
exemption. It runs identically on a machine that has torch, which grepping for `import torch`
would not.

**Proof it is not vacuous:** with the pre-fix import restored, two tests fail
(`test_only_the_declared_modules_need_torch_to_import` and the `byte_batch` parametrisation).
Re-verified before the fix was kept.

## A second real bug, found by ruff and confirmed by test

`byte_decider.py:239`, inside `score_from_hidden` — the method whose entire purpose is to
reuse already-encoded states — called `self.encode_context(context_ids, context_mask)`.
`context_ids` is not a parameter of that method. Every `forward` routes through it, so the
model would have raised `NameError` on any real call.

It had been reported to the user as "19 tests passed". **That claim was false.** The shim
driving the torch-gated tests was swallowing the failures. The corrected driver reports
4 failures against that line, and `h = hidden` fixes it.

The driver is now only trusted after being run against known-bad code first; it reports
`NOT RUN` for any fixture it cannot supply, and its exit code is checked.

### The seams that were reused rather than restated

* **The abstain row** stays `heads.plan_span_batch`'s — the one function pinned against
  `answer.rs`. `byte_train` never computes it. `byte_batch.span_supervision` converts line
  *ordinals* to byte *offsets* so the round trip through that function is possible; that
  conversion is the sixth instance of this repo's "one name, two quantities" shape and it
  lives in exactly one place, with a test that reads both units.
* **The span head** is `heads.SpanPointerHead`, unmodified. It takes `[K, L, H]`, which is
  what `ByteDecider.encode_context` already returns.
* **Cap, LR schedule, checkpoint cadence, cost, approval gate** are all read from the shared
  `RunControl`. `train_rung0` re-decides none of them (rule 2).

### One encode, two heads

`Rung0Model.losses` encodes the context once and hands the same `hidden` to the option head
and the pointer head. Two encodes would diverge under dropout and the span head would point
into states the option head never saw. This is exactly what the `score_from_hidden` bug above
had broken, so it is asserted directly:
`test_the_context_is_encoded_once_for_both_heads`.

### The end line is carried, not fabricated

`SpanPointerHead` trains a start pointer **and** an end pointer. `ByteDecision` carried only
the start line, so the end pointer would have been trained on the start — a fabricated target
that still produces a falling loss. `ByteDecision.gold_span_end_line` now carries the real end,
resolved through `span_end_offset` with the same phantom-final-line check, and `_validate`
refuses half an abstention.

## The four rules that were silently diverging

The first version of `train_rung0` re-implemented gradient accumulation and got **three of
the four rules wrong** within an hour of being written. `trainer._train` had all four right.

| Rule | `_train` | `train_rung0`, as first written |
| --- | --- | --- |
| 1. Never apply a partial group | raises when the source ends mid-group | silently dropped the tail |
| 2. Check the cap only at a group boundary | `if not group_losses and control.expired()` | checked unconditionally — discarded a half-accumulated gradient |
| 3. A non-finite loss stops the run | raises | **no check at all** — would have trained on NaN while printing a loss curve |
| 4. The group's loss is its own mean | yes | yes |

A fourth divergence sat beside them: exhausting `max_batches` returned
`termination="steps_exhausted"`, making a truncated run indistinguishable from a complete
one — the exact failure this repo's tri-state rules exist to prevent.

**All four now have one owner.** `qd_train.run_control.AccumulationGroup` holds the rules and
writes the messages; both loops drive it, and each passes the exception *type* it raises
(`TrainerContractViolation` is pinned by `test_trainer.py`, so the type is domain vocabulary
while the rules are shared). `test_trainer.py` passes unchanged — 37 tests — which is what
makes the extraction faithful rather than merely green.

The loops themselves stay separate, and that is a decision rather than a deferral: one loop
serving both batch types needs four injection points (index, supervise, accumulate, padding
accounting), which is a framework, not a simplification.

## Three more gaps closed in rung 0's own code

* `byte_batch.MAX_PADDING_WASTE` was a **second copy** of `artifacts.MAX_PADDING_WASTE` that
  nothing enforced. It now imports the one owner — and `train_rung0` reports padding as a
  **tri-state gate** against it, not a bare float nobody read. A run that consumed no
  micro-batches reports `NotRun`, because 0.0 would read as perfect bucketing on a run that
  trained on nothing.
* `byte_train.PAD_ID` was a dead re-export, and a dangerous one: `shards.PAD_ID` is `0`
  (a token id) while `byte_context.ID_PAD` is `256` (a byte id). Two near-identical names
  for two different quantities, with nothing using the second. Deleted.
* `BatchTensors.batch_size` was computed and never read. Deleted. `Rung0Result.rows` was
  also unread, and now has a test instead.

## The suite flakiness, explained

Earlier in this lane the suite twice showed failures and a skip count moving between 5 and
18. That is now traced.

**The 13 flipping tests are `test_wire_golden_corpus.py`'s**, and the mechanism is
`qd_wire.corpus.load_corpus`: it returns `NotRun` when `fixtures/wire/` is absent, empty,
manifest-less, or names files that are not on disk. **Every one of the 58 fixture files
carries mtime `21:30:39` today** — they were rewritten mid-session by the XLANG-RS
generator (`QD_WRITE_FIXTURES=1 cargo test -p qd-runtime --test wire_fixtures`). Before that
write the corpus read as `NotRun` and 13 tests skipped; after it, they run and pass. The
manifest and the directory now agree exactly: 58 named, 58 on disk, no strays, no missing.

**A concurrent writer in this same worktree is confirmed, not inferred.** Files this lane
never touched changed during it: `python/qd_train/artifacts.py` at 21:30:04,
`python/qd_train/ledger.py` at 21:42:52, all of `fixtures/wire/` at 21:30:39, and
`gaps.jsonl` gained `GAP-TESSL-AUDIT-BKC-CHECK-DEAD` at 22:10. Note that
`gitpulse_collision_risk` reports 0 overlapping files — that facet compares *worktrees*, and
this writer is in the same one, so it is invisible to it. A clean collision report is not
evidence of no concurrent writer.

**The residual is closed too — a 40-run stress pass caught it live at run 35.** The
mechanism is not subtle once seen: *the concurrent lane's half-written files are picked up
mid-edit by whatever test run happens to be in flight.* Three independent instances were
captured within ten minutes:

* `python/tests/test_shards.py` (mtime 22:23:48) referenced `byte_line_starts`, a symbol
  that did not yet exist in `shards.py` — a test committed to disk ahead of its
  implementation. `NameError`.
* `test_shards.py` cited a `GAP-` id (an `RT-WIRE-CONTEXT` one) before its record was
  appended to `gaps.jsonl`, so `test_wire_gap_pins.py` failed on a dangling citation. The
  id is deliberately not spelled in full here: writing it into a tracked file is what makes
  it dangle, and `test_gaps_ledger.py` caught this document doing exactly that.
* `python/tests/test_qd_data_wire_agreement.py`, created at **22:30:14** and untracked,
  contains a literal `</content>` tag at line 506 — a malformed mid-stream write from an
  agent, which made the whole suite **uncollectable**, not merely red.

That is the same phenomenon as the earlier `test_ledger.py` failures, and it reproduced:
`test_ledger.py` was rewritten at 22:30:16 and two different tests in it failed 57 seconds
later. The tests are hermetic *as source*; what varied was the source. Nothing was wrong
with `qd_train.ledger` and nothing needed fixing in it — which is why 60/60 runs in
isolation were clean and no mechanism could be found by reading the code.

**Practical consequence for the next lane:** a full-suite result from this worktree is only
meaningful if nothing else is writing to it. Check `ls -lT` on the failing file before
believing a failure. This lane's own surface was measured separately and is green
(233 passed, 4 skipped across its eleven test files).
