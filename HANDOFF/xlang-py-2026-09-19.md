# XLANG-PY — the Rust -> Python half of the wire contract

**Lane:** XLANG-PY · **Date:** 2026-09-19 · **Paired with:** XLANG-RS (owns `crates/`, `docs/schema-api.md`, `fixtures/wire/`)

## What this lane was for

`docs/schema-api.md` specifies the **request** side with two implementations that a
cross-language test drives against each other, and the **answer** side with one example
object and one implementation. A contract with a single implementation cannot disagree
with itself, which is how `GAP-RT-WIRE-CONTEXT-ENCODING` and
`GAP-SCHEMA-LABEL-SET-HASH-TWO-MEANINGS` each survived two green suites.

This lane built the second implementation and the checks that make it break when the
first one moves.

## The seams this lane leaves behind

Three, all executable. None is a paragraph.

1. **`fixtures/wire/`** — XLANG-RS generates it, `qd_wire.corpus` reads it *through
   `index.json`*, never by globbing. A file the manifest names and the directory lacks,
   or a file present that nothing names, is a failure that names it. Unknown field and
   missing field are both refusals; there is no lenient mode.
2. **`contract.py` vs the Rust source** — re-derived and compared on every test run, with
   field *types* carried alongside names, so a `usize` that becomes a `String` under the
   same name fails too.
3. **The live binary** — `target/debug/qd` driven into the parser. Reports `NotRun` when
   the binary is missing **or older than any `.rs` under `crates/qd-runtime/src`**. That
   fired for real during this lane (RS edited `render.rs` mid-run) and is the reason the
   probe never agrees with a stale build.

## What could not be verified, and why

- **`qd serve`** — only `qd oneshot` is exercised. The socket path shares the reply
  encoder (`serve.rs:235` and `:276` both call `serde_json::to_vec(&Response)`), so the
  bytes should be identical, but that is **inferred from a file read, not measured**.
- **A non-reference backend** — no model backend exists in this build, so every answer
  parsed came from `reference-deterministic-v1`. A real backend's `degraded: false`
  answers are covered only by the `answer-not-degraded.json` fixture.
- **GitPulse** — untrusted for this repo; every `gitpulse_*` call returns
  `REPOSITORY_TRUST_REQUIRED`. No collision check was run before touching shared files.
  Recorded, not worked around.
- **DevMap** — served the Rust symbol lookups, but reported
  `degraded_reason: "source tree differs from the indexed generation"` throughout, so
  every Rust fact in this lane was confirmed by reading the file, not by the graph alone.

## The exact first command for the next lane

```
cargo build -p qd-runtime --bin qd && \
  QD_WRITE_FIXTURES=1 cargo test -p qd-runtime --test wire_fixtures && \
  .venv/bin/python -m pytest python/tests/test_wire_golden_corpus.py -v
```

Build first, regenerate the corpus, then read it from Python. If the middle step changes
any file under `fixtures/wire/`, the third step is what says whether Python still
understands the envelope — and if it does not, it names the field.

To regenerate `python/qd_wire/contract.py` after a Rust change:
`PYTHONPATH=python .venv/bin/python -m qd_wire.rust_source`
