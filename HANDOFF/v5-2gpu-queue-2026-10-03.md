## Read first: the COST conflict (GAP-V5-2GPU-COST-INSTANCE-RATE-REFUSED-AT-ONE-GPU-2026-10-03)

The spec asks for `--usd-per-hour 8.38` (the whole instance) with `--usd-per-gpu-hour 4.19`. The
tool refuses that pair on a lane's run:

- A lane runs with `CUDA_VISIBLE_DEVICES=<N>`, so the tool counts one GPU.
  - `tools/run_cost.py:46` returns `torch.cuda.device_count()`.
  - That this count honours `CUDA_VISIBLE_DEVICES` is **inferred**. It was not run on a CUDA
    box.
- At `n_gpus=1`, `CostEstimate` raises "disagree at n_gpus=1" (`python/qd_train/run_control.py:515-521`).
- `8.38` alone would price each lane's run as the whole box: $75.42 per 32,400 s cap, not $37.71.

**What the lanes pass instead.** Each lane passes
`--instance <V5_INSTANCE>:gpu<N> --usd-per-hour 4.19 --usd-per-gpu-hour 4.19`.

- The tool accepts this at one GPU.
- It refuses it at two (`run_control.py:508-514`), so a lane that somehow saw both GPUs fails
  before its tower loads.
- Both rates stay pins, and `v5_pins_check` requires instance = per-GPU x 2.

`test_the_tool_refuses_the_whole_instance_rate_on_one_visible_gpu` checks all of this against the
tool's own `CostEstimate`, and it passed. **Open:** the lead confirms this reading of "price per GPU
exactly as the tool does".
