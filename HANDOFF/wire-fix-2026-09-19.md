## Why base64 is canonical-only, on both sides

This is the one design decision taken beyond the brief, so it is stated plainly.

`base64.b64decode(validate=True)` checks the **alphabet** but not the bits a partial quantum leaves
unused. `Zg==` and `Zh==` therefore both decode to `b"f"` in Python. Two distinct strings naming one
context is the same "undefined" the whole fix is about, and it would put a digest over the encoded
form at odds with a digest over the bytes.

So `qd_runtime::b64::decode` rejects non-zero slack bits directly, and
`qd_data.schema.decode_context` re-encodes and compares to reach the same place. Both lanes are
strict at the same edge, and `base64_that_decodes_but_is_not_canonical_is_refused` plus the
cross-language negative set assert it rather than trusting it. Had only Rust been tightened, the
result would have been a payload Python accepts and Rust refuses — the bug being fixed, one layer
down.

## What the incoming report got wrong

Two of the five items in the brief were **already done, or done differently than described**. Both
were verified against the live files before acting, which is the only reason the work did not
duplicate or undo another lane's.

1. **`python/qd_data/render.py::unescape` was not missing its `\uXXXX` arm.** The data lane had
   already added it (`render.py` lines 232-253) and had already raised
   `ESCAPE_WORST_CASE_GROWTH` to 6 and `max_rendered_bytes` to 802816. Verified by running all
   twelve break-set members through both escapers: all round-trip. What *was* missing was
   **coverage** — the round-trip was asserted only by a hypothesis property over `st.text()`, which
   is not guaranteed to draw U+2028 or a bare NUL, so it stayed green throughout the window in which
   the arm was absent. That is the fix that shipped here.

2. **The 2x growth bound was not stale "in both lanes".** It was stale in **one** — Rust — and the
   consequence was worse than the brief described. The Python lane was at 6x / 802816 while
   `qd-runtime` was at 2x / 393216, so the two lanes were **refusing different requests**: a
   131072-byte NUL-dense context renders to 786432 bytes, which Python accepted and the runtime
   refused with `rendered_prompt_over_cap`. That is a second live incompatibility of the same shape
   as `GAP-RT-WIRE-CONTEXT-ENCODING`, and the Rust source comment asserting the two lanes were
   "kept identical on purpose" was false when it was written.

3. **DevMap is available for this repo**, contrary to the brief and to `GAP-RT-DEVMAP-CORRUPT`.
   `devmap_status` with `repo_path=/Users/bharath/Code/research/qwen-decision` resolves
   `repository.root` correctly and reports a healthy per-repo store at
   `.devmap/codeintel/devmap.sqlite` — generation 39, 1971 nodes, 6834 edges, `pending_count` 0,
   `degraded_reason` null, `is_fresh` true. That is a **different store** from the 2 GB umbrella
   index at `.devcouncil/codeintel/devmap.sqlite` that `AUDIT/devmap-false-corruption.md` is about.
   Recorded as `GAP-WIREFIX-DEVMAP-AVAILABLE-CONTRARY-TO-BRIEF`.

   **GitPulse is genuinely unavailable**: `gitpulse_status` returns
   `[untrusted_worktree] REPOSITORY_TRUST_REQUIRED` for this path. `GAP-RT-GITPULSE-UNTRUSTED`
   stands, and this lane could not see other worktrees, live agent sessions or contended files. The
   stack lane's concurrent 15 tests are the visible evidence that something else *was* writing.

## What is still underspecified in `docs/schema-api.md`

Answering the question the brief asked. These are gaps in the **contract**, not in the code:

1. **The answer envelope has no wire specification at all.** The doc shows one example JSON object
   for the answer and nothing else: no statement that `value` is absent exactly when `noul` is true,
   no statement that `conformal_set` is `null` for `span`, no field-presence rules, and no
   `status` tag — yet `qd-runtime` emits `{"status":"ok"|"refused"|"error"}` as the discriminant of
   a three-variant union. A second implementation written from this document would not produce
   what `qd-runtime` produces. This is the same shape of hole that `context` had, and it is the
   larger of the two. `GAP-XLANG-NO-PY-ANSWER-PARSER`.

2. **`expect` is not in the document.** `HashExpectation`'s five fields, that all are optional, and
   that absent means "pinned nothing" are all real behaviour with no line in the contract. The
   refusal table names "tokenizer / weight / head / label-set hash != build" without saying how a
   caller pins one, and `calibration_hash` — a sixth thing the runtime checks — is not in that table.

3. **`label_set_hash` means two different things** and the document uses the name without saying
   which. `GAP-XLANG-LABEL-SET-HASH-TWO-MEANINGS`.

4. **The refusal table names conditions, not identifiers.** Until this change, neither lane's
   `kind`/`check` strings were in the document at all; the four context ones are now, and the other
   thirty-two are not. A caller branching on a refusal has no specified vocabulary.
   `GAP-XLANG-REFUSAL-VOCABULARIES`.

5. **Unknown fields are unspecified.** The document does not say whether a request carrying a field
   the build does not know is refused or ignored, and the two lanes chose differently.
   `GAP-XLANG-UNKNOWN-FIELD-LENIENCY`.

6. **Neither cap is in the document.** `max_context_bytes`, `max_rendered_bytes` and the escape
   growth factor determine which requests are answerable, and all three live only in code — in two
   copies, which is precisely how they came to disagree. The refusal table says "`context` over the
   configured cap" without saying what configures it.

7. **The `span` answer's field names are shown only inside an example.** `{start_line, end_line}`
   appears in the Answer JSON and nowhere as a requirement, which is how `qd-mutate` shipped
   `{"start","end"}` against a `deny_unknown_fields` struct (`GAP-MUTATE-SPAN-WIRE-NAMES`).

## For whoever picks this up

The cross-language test is the deliverable that matters more than the encoding fix. Two independent
incompatibilities were found in this repo in one day — `context_b64` and the span field names — both
between suites that were fully green on each side. That is not two accidents; it is what happens
when every test exercises one lane's encoder against that same lane's decoder.
`crates/qd-runtime/tests/wire_context_crosslang.rs` is the structural answer, and it is written to
**fail rather than skip** when a shared type appears on the side that does not have one yet. Keep it
that way.
