## Why it was needed

`docs/hardening.md:133` — *"f64 sequential reference in Rust is the golden; K1/K2 match at
1e-4 relative in fp32."* Each published case ships two outputs: `y_chunked` (f32) and
`y_seq_f64` (f64). **Only the f64 one is an independent reference.** `read_npy` could not
load it: the match had arms for `<f4` (`:80`) and `<i8` (`:113`) and `other => Err` at
`:146`, so all 13 references returned `unsupported dtype <f8`.

The trap this closes: the one loadable f32 output, `y_chunked.npy`, is the output of the
*same chunked algorithm* K1–K7 are meant to validate. A lane that hit the refusal and
reached for it instead would have written a self-consistent test that proves nothing —
the vacuous-test shape this project has already hit three times.

Separately, `src/npy.rs:1-2` claimed **"f32 / i64 / f64 scalar"** while the implementation
supported no f64 at all. That docstring sat exactly where a kernel author would read it and
conclude the golden loads. It now states what the code does.

# Round 2 — the f64 sequential reference in Rust

`docs/hardening.md:133` calls for "f64 sequential reference **in Rust**". It now exists:
`tests/common/gdn.rs`, wired into the shared test scaffolding so `tests/gdn.rs` (K1–K7)
can use it. This is what lets a kernel be judged at a shape nobody generated a fixture
for, and it stops the operator definition living only in another repo's Python.

Operator source: `MLSystemsLab/nanolab/mixers.py:767-773` and `_sequential` at `:816`.

```text
repo:      S <- a*S + b * k (v -     S^T k)^T     (nanolab's DEFAULT)
published: S <- a*S + b * k (v - a * S^T k)^T     (arXiv:2412.06464 eq. 8)
y = S^T q                                          (against the UPDATED S)
```

## Result

The Rust reference reproduces the Python-generated golden **bit-for-bit on all 13
cases**, including `L8191`'s 8191 sequential steps — so the two agree on summation
order, not merely on semantics. Verified by setting the bound to exactly `0.0` and
watching it pass.

The committed bound is `1e-12`, not `0.0`, on purpose: bit-exactness across a
Rust/NumPy boundary holds by a coincidence of accumulation order that a torch or numpy
upgrade could change without anything being wrong, and a suite that fails on a
dependency bump teaches people to ignore it. Both real defects this pair has caught
still fail `1e-12` by orders of magnitude.

## A fixture-contract defect, found by implementing against it

`GAP-TESSL-GDN-FIXTURE-STORES-UNCLAMPED-ALPHA` (open).

`gdn_published_L65_tinyalpha_alpha.npy` stores `1e-8` in all 390 entries, while its own
manifest declares `alpha_clamp = [0.0001, 1.0]` and the golden was generated **with the
clamp applied**.

| alpha used | reproduces the golden to |
| --- | --- |
| stored `1e-8` | 3.990e-04 abs / **8.356e-05** rel |
| clamped to `[1e-4, 1.0]` | 8.882e-16 abs / **1.860e-16** rel |

An error small enough to read as accumulated rounding and far too large to be it. This is
the rule-9 hazard in a second form: rule 9 guards a golden generated under the wrong
*operator*; this is a golden generated from different *inputs* than the ones shipped beside
it. The other 12 cases sit inside the clamp, so `alpha_mode="tiny"` is the only case that
exposes it — presumably what it was built for.

**Not fixed here.** Regenerating or renaming a published fixture is a change to a parity
target, and repo rule 2 makes those read-only to an agent. The reference applies the clamp
internally instead, so a caller cannot forget it and get a plausible wrong answer — which is
exactly what happened on first implementation.

## Cross-checks that fell out

- The repo rule diverges from the published golden by **1.469695** on `L65_tinyalpha`,
  reproducing that manifest's recorded `max_abs_published_vs_repo = 1.46969473361969`
  exactly. Smallest divergence across the L>1 cases: **1.448e-01**.
- **The two rules coincide exactly at L=1.** At `t=0` the state is zero, so `a·Sᵀk` and
  `Sᵀk` are both zero. A single-step problem cannot distinguish the rules — worth knowing
  before using one as evidence. The test asserts equality there rather than divergence;
  the first draft asserted divergence and was wrong.
