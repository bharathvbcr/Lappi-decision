## What changed

**`a81d1a7`: the code and the tests.**

`python/qd_train/containment_strip.py`:

- **The strip.**
  - (1) The question line is stripped by constancy, as before.
  - (2a) Option values every row of the family-slot carries, by membership, as before.
  - (2b) New: every option value of the four intent.* families. They are
    `CLOSED_VOCABULARY_FAMILIES`, and a test holds that set equal to the task families sourced
    from `clinc/clinc_oos`.
  - For a (2b) group, `Constants.options` is the union of every value seen. So the existing
    `stripped`, `n_stripped` and `stripped_sha256` cover exactly what was stripped.
- **The refusal.** `strip_template` raises `ReplayRefusal` for any (2b) row whose stripped
  text is not its context block byte for byte. The message names the cause:
  - a group of fewer than 2 rows, whose question line is therefore not stripped;
  - no context block;
  - a question line that is not constant.
  - This is how the lane read "a group of fewer than 2 rows strips nothing" together with the
    (2b) refusal. A lone intent.* row is refused, never compared with its template.
  - Under `apply=False` (measurement only) nothing is refused.

**Every flag that must equal the v5 build's pipeline call.** The hook checks some flags
through the attestation's `corpus`. It checks nothing marked "not in the identity".

| flag | in the identity |
|---|---|
| `--rev` | yes, the resolved rev |
| `--no-repo-history` | yes |
| `--commitpackft` | by directory name |
| `--max-pairs`, or the pipeline's default (refused here under `--no-repo-history` without `--commitpackft`) | yes |
| `--defect-class` | **by directory name only** |
| `--defect-download` | **not in the identity** |
| `--defect-max-rows`, or none (v4 passed none) | yes |
| `--defect-noul` | by its manifest's `examples_sha256` |
| `--general-record` | by sha256 |
| `--general-max-rows` | yes |
