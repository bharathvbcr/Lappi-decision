## The four things the lane was asked to prove

### 1. The two modes share one contract — asserted, not commented

`tests/two_modes_one_contract.rs` sends **the identical bytes** down a live Unix socket and through
the in-process sidecar and compares the replies byte for byte, including the framing newline. It
does this for all three outcomes separately, because sharing a code path for the happy case and
diverging on the errors is the divergence that matters:

* an answer, a refusal, a backend failure, a malformed line, an unknown control op, an ambiguous
  envelope — six payloads, all byte-identical;
* `the_dcverify_fallback_answers_exactly_what_the_socket_would_have` runs the real dcverify path:
  it records what a live agent answers, then answers the same request with nothing listening and
  asserts the bytes match;
* `the_socket_is_preferred_when_one_is_listening` asserts the fallback is a fallback.

The mechanism is that `Service::handle_line` is the only thing in either mode that looks at a
request or builds a reply. `qd serve` and `qd oneshot` differ only in where the bytes come from.

### 2. A refusal is structurally distinguishable from `noul`

`tests/refusal_is_not_noul.rs`, four independent axes over **every** variant of both error enums
(34 `Refusal`, 12 `BackendError`):

1. **Different `Response` variants.** `Refused` and `Error` are not `Ok`; a caller matches
   exhaustively. There is no `From<Refusal> for AnswerEnvelope` and no way to build a `SlotAnswer`
   from either error type.
2. **`caller_reading()` is total, and nothing maps wrong.** No refusal and no backend error yields
   `CallerReading::ModelAbstained`; an all-`noul` answer does, and only it.
3. **No shared key at any depth.** A refusal payload carries no `slots`, `value`, `score`,
   `conformal_set` or `noul` key anywhere in its JSON; an abstention carries no `refusal` or `error`
   key. The check walks keys, never substrings — `Refusal::ReservedOptionName` legitimately carries
   the string `"noul"` as a *value*, and a substring test would have to be weakened until it proved
   nothing.
4. **Deserializing one as the other fails**, for every variant.

Coverage is kept true over time by `kind_of` and `backend_kind_of`: exhaustive matches with no
wildcard arm, so **adding a variant to either enum fails to compile that test file** until it is
listed.

The specific bug the contract names has its own test:
`a_hash_mismatch_does_not_read_as_model_humility` pins a wrong `tokenizer_hash`, asserts a
`RequestRefused` carrying `which: tokenizer` and both compared values, and then asserts the same
request without the bad pin is *answered* — so the refusal is attributable to the hash.

### 3. `readonly` leaves the state buffer hash-identical

`tests/readonly_slot_isolation.rs`. A test that only asserts "the hash did not change" passes
against a backend that never touches the state, so three assertions stand together:

1. a read-only decode leaves the hash identical;
2. **a write-back decode changes it** — so the buffer is reachable and the hash is sensitive;
3. a backend that writes back while the caller asked for read-only is **caught**, with the slot
   index and both hashes in `BackendError::ReadonlyViolated`, and the whole request fails rather
   than answering.

Then the property itself: `slot_two_does_not_depend_on_slot_one` decodes slot 2 after slot 1 and
again alone from a fresh snapshot of the same prefill, and asserts the logits are equal.

This is **enforced at runtime**, not only tested: `answer::readonly_decode` hashes the state either
side of every decode on every request. Where a backend declares `state_host_visible: false` the
check is `SlotIsolationCheck::NotRun` with a reason and the answer is marked `degraded` — never a
silent pass. `an_unverifiable_state_degrades_the_answer_rather_than_passing_silently` has a control
(a backend identical except that its state *is* visible) which must answer clean, so the `degraded`
is attributable to the unrunnable check.

## Scoping: there is no model, and nothing pretends otherwise

No Metal kernel exists and none was written. `backend::DecisionBackend` is the seam K1-K7 will
implement, with exactly the operations the contract's answering procedure names: `prefill`,
`snapshot`, `decode_slot` with a `DecodeMode` (the `readonly` flag), and `pooled_features` for the
registered route.

`Runtime::build` with no backend enabled returns `BackendError::Unavailable` naming what is absent
and why. It is a typed error in the `Error` variant of `Response` — **not an empty answer and not a
`noul`**. `with_no_backend_a_valid_request_is_an_error_not_an_abstention` asserts the reply contains
no `noul` and no `slots` key at all.

`reference::ReferenceBackend` is the only backend that exists. It:

* **refuses to serve unless explicitly enabled** — `ReferenceBackend::new(false)` returns
  `ReferenceBackendNotEnabled` from every operation, `RuntimeConfig::default()` has it off, and
  `the_shipped_idle_timeout_is_the_plans_ten_minutes` asserts the default stays off;
* is **honestly named**: `reference-deterministic-v1` appears in `AnswerEnvelope::backend` on every
  answer it produces;
* declares `is_model: false`, so the runtime marks **every** slot it answers `degraded`.

Its scores are a SHA-256 of the prompt. They carry no information about the question. What it *is*
faithful about is structure: it prefills once, exposes a host-visible state buffer, leaves it
byte-identical under `ReadOnly`, and genuinely mutates it under `WriteBack` — which is what makes
the slot-isolation test a test rather than a tautology.

Its calibration numbers were not fitted on anything: `GAP-RT-CALIBRATION-NOT-FITTED`.

## Lifecycle (`docs/hardening.md` §6)

`tests/lifecycle.rs`, 15 tests. The timeouts are milliseconds because a test that waits ten minutes
is a test nobody runs; the shipped ten minutes is asserted separately.

* **Idle eviction** at `ServiceConfig::idle_timeout`, default 600 s. `reap_idle` refuses to evict a
  runtime used a moment ago and evicts one past the window; a reaper thread does it unattended; the
  next request rebuilds (`builds == 2`).
* **Cold start is measured**, around the real build. With a factory that takes 25 ms, the reported
  `last_cold_start_ms >= 20`. Before any build it is `None`, never `0` — "never built" is not the
  same fact as "built instantly".
* **Poison → DEGRADED → rebuild.** A backend that poisons on prefill causes one rebuild, and the
  answer that comes back is flagged `degraded` at envelope and slot level. A **control** (a clean
  model backend answering not-degraded) runs first, so the flag is attributable to the rebuild.
  A runtime that poisons again immediately after a rebuild stops with `rebuild_failed` rather than
  looping; a rebuild that cannot build reports `rebuild_failed`, not the original error.
* **A slow request does not wedge the agent.** With one 600 ms request in flight, four others
  complete in under 300 ms. The mechanism is that the service mutex is held only for bookkeeping and
  never across a decode: a request locks to clone an `Arc<Runtime>` and unlocks before it asks the
  backend anything.
* **Every bound is a bound.** Concurrency (`overloaded` beyond `max_in_flight`), wall clock
  (`deadline_exceeded`, carrying the *configured* limit rather than the zero left when it fires),
  payload (`payload_over_cap`, measured, and the connection closed so a half-read line cannot
  resynchronise the protocol onto the middle of a payload), connections, and slot fan-out
  (`MAX_SLOTS = 32`).
* The socket is created mode `0600`. Binding over a **live** socket is refused with `AddrInUse`
  rather than silently stealing the running agent's callers; a **dead** socket file from a killed
  agent is cleared.

One live bug was found and fixed here: `GAP-RT-SHUTDOWN-ACCEPT-WAKE`. A `shutdown` op set a flag
that the blocked `accept()` could not see, and the integration test hid it by dialling the socket
itself afterwards. The test no longer dials, failed against the pre-fix code, and passes now;
re-verified against the live binary.

## What the next lanes need from this one

**Kernel lane (K1-K7).** Implement `backend::DecisionBackend`. Four operations, and three things
the trait says that the contract does not:

* `decode_slot` takes `&mut StateSnapshot` on purpose — the runtime hashes the state either side and
  will reject a write-back under `ReadOnly`. If the state cannot be exposed to the host, say so via
  `BackendIdentity::state_host_visible: false` and accept that every answer is then `degraded`.
* A maximal `choice` slot reads **17** head rows, not 16 — now stated in `docs/schema-api.md`
  ("The letter budget"), which another lane amended while this one ran
  (`GAP-RT-NOUL-LETTER-BUDGET-SETTLED`).
* A `span` slot is **two** pointer decodes over `line_count + 1` rows (`GAP-RT-SPEC-SPAN-DECODE`) —
  agree with this or change it, but write it down before K2.

**Data / training lane.** The renderer is pinned byte-for-byte against your `render.py` in
`tests/render_contract.rs`. If you change a marker, an escape rule or a cap, that test fails, which
is the intent. Two things to fix on your side: `GAP-RT-PY-UNESCAPE-HEX` and a decision on
`GAP-RT-WIRE-CONTEXT-ENCODING`.

**Eval / calibration lane.** `Runtime::with_backend` takes the calibration table as a parameter and
`CalibrationTable::validate()` refuses an unusable one at construction; `CalibrationTable::hash()`
is what `expect.calibration_hash` pins. Read `GAP-RT-SPEC-PERMUTATION-DERANGEMENT` before
implementing the permutation-consistency gate.

**Product wiring.** DevType uses the socket; dcverify uses `qd oneshot --socket <path>`, which falls
back to the in-process sidecar and says on stderr which one served. Exit codes: 0 answer, 2 refusal,
3 backend error, 1 could not run. Nothing in this crate emits `PASS`, `allow`, or discharges
anything — it answers or it refuses.
