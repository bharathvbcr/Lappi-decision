## What changed

- **Layout.** Both renderers now write this prefix:
  `<|qd_begin|>\n<|qd_prompt_format|>2\n<|qd_schema_version|>1\n<|qd_task|>T\n<|qd_route|>R\n<|qd_context_begin|>\nC\n<|qd_context_end|>\n<|qd_question|>Q\n`.
  - Then come the slot suffixes, which are unchanged.
  - The renderers are `python/qd_data/render.py` and `crates/qd-runtime/src/render.rs`.
  - `M_FORMAT = "<|qd_prompt_format|>"` joins `MARKERS` in both, right after `M_BEGIN`.
    `PROMPT_FORMAT = 2` in both.
  - The wire `schema_version` stays 1.
- **Release.** `MANIFEST_FORMAT = "qd-release.v2"` (`crates/qd-runtime/src/release.rs`).
  - `Manifest::prompt_format` runs in `open_tower` and in `Ensemble::open`.
  - It refuses three cases, all as `ReleaseRefusalKind::PromptFormat` (`as_str` is
    `"prompt_format"`):
    - an absent stamp;
    - a stamp that is not a positive integer;
    - a stamp that is not `render::PROMPT_FORMAT`.
  - A v1 release is refused by its format, as `Manifest`.
  - `Tower::prompt_format()` is public.
- **The other direction.** The pre-change (v4-era) runtime refuses a v2 release:
  `format is Some("qd-release.v2"), not "qd-release.v1"` [V, `build/fmt-logs/pre-qd-runtime.log`].
- **Export.** `crates/qd-export/src/export.rs` `read_source_manifest` reads `prompt_format`.
  - Absent means 1.
  - Any value other than a JSON integer of at least 1 is refused as `SourceManifest`, and nothing
    is left behind.
  - The release manifest records the value in three places:
    - `expected_identity.prompt_format`;
    - `source.prompt_format`;
    - `source.prompt_format_stated`.
  - `ExportSummary.prompt_format` carries it too.
  - The ensemble manifest (`qd-ensemble.v1`, format unchanged) now carries the members'
    `expected_identity.prompt_format`.
  - `crates/qd-export/src/{main.rs,lib.rs}` neither print nor document the field. Those files
    were outside this lane.
- **Shards, Python** (`python/qd_train/artifacts.py`, `shards.py`):
  - `ShardHeader.prompt_format: int = 1`. It is serialized and hashed only when it is not 1, so
    v4 header hashes do not move [V, `test_prompt_format_v5.py`].
  - `__post_init__` and `from_json` refuse a bool, a non-int and anything below 1.
  - The writer stamps `PROMPT_FORMAT`.
  - `ShardReader` calls `header.require_prompt_format(where=...)`, so a set of another format is
    refused.
- **Shards, Rust** (`crates/qd-train/src/shards.rs`):
  - The hash now matches Python's, including `exclusions_sha256` and `contrast_rows`. Before
    this, the Rust reader refused every header that carried either field.
  - `prompt_format` is parsed and hashed, but not compared against a constant. qd-train
    reaches `qd-runtime` only through qd-export.

## What L-v5-train must use (exact)

- **Python constant:** `from qd_data.render import PROMPT_FORMAT`, an `int` equal to 2.
- **Shard header:** `ShardHeader.prompt_format`, an `int`; a JSON header without it reads as 1.
  - `ShardReader(...)` already refuses a set whose format is not `PROMPT_FORMAT`.
  - Other readers call `header.require_prompt_format(where=<path>)`, which raises
    `ShardContractViolation`.
- **Recipe key** (owned by L-v5-train):
  - Write `recipe["prompt_format"] = reader.header.prompt_format`, taken from the training
    shard set, never from the constant.
  - At eval and `--score-checkpoint` time, refuse when
    `ft["recipe"].get("prompt_format", 1) != PROMPT_FORMAT`.
- **The key qd-export reads.** It is the top-level field **`prompt_format`** of the checkpoint's
  source manifest.
  - **Path:** `<source file name>.manifest.json` beside the averaged checkpoint, or the file
    `--source-manifest` names (`crates/qd-export/src/export.rs:320-327`, `main.rs:6`).
    `tools/ckpt_average.py` writes that path (`MANIFEST_SUFFIX`, line 117; `write`, line 775).
    The comment at `export.rs:63` cites `ckpt_average.py:188`, a line number that has gone stale.
  - **Type:** a JSON integer, at least 1. `true`, `2.0`, `"2"` and `0` are refused.
  - **Absent:** read as 1.
  - Both writers must copy it from the recipe: `tools/ckpt_average.py::write` and the qd-train
    Metal export manifest.
- **Rust:**
  - Constant: `qd_runtime::render::PROMPT_FORMAT: u32`.
  - Header field: `qd_train::shards::ShardHeader.prompt_format: u64`.
  - A refusal in the Rust trainer would need `qd-runtime` as a direct dependency, or a
    re-export.
