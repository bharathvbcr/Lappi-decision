the asymmetry the way the training side closed its own (`python/qd_train/artifacts.py`,

Change a field here and the other lane breaks loudly instead of silently accepting it.

## The corpus — the seam XLANG-PY consumes

`fixtures/wire/` — **58 files**: 8 answers, 37 refusals (all 36 kinds; `hash_mismatch` twice, by
`which`), 12 backend errors, plus `index.json`.

```text
# check (the default, and the gate — fails on any drift)
cargo test -p qd-runtime --test wire_fixtures

# regenerate, after an intended envelope change
QD_WRITE_FIXTURES=1 cargo test -p qd-runtime --test wire_fixtures
```

Comparison is the default deliberately: a corpus that regenerates on every run records whatever the
code currently does and can never disagree with it, which is not a gate. The generator is
`crates/qd-runtime/src/fixtures.rs`; it removes strays, so a leftover file from a renamed variant
cannot teach the other lane a shape this build no longer emits.

Answers are produced by the reference backend, whose scores are counter-mode SHA-256 over the
prompt — the same bytes on any machine, which is what makes the corpus comparable rather than
merely regenerable.

### Defects found and fixed, each with the pre-fix failure observed

**1. `value` and `noul` were one fact spelled twice, with nothing enforcing agreement.**
The derived `Deserialize` accepted both contradictory shapes. Observed against unmodified code:

```
a_slot_answer_carrying_both_a_value_and_an_abstention_is_refused ... FAILED
  called `unwrap_err()` on an `Ok`: SlotAnswer { value: Some(Choice("stub")), …, noul: true }
a_slot_answer_carrying_neither_a_value_nor_an_abstention_is_refused ... FAILED
  called `unwrap_err()` on an `Ok`: SlotAnswer { value: None, …, noul: false }
an_unknown_field_on_the_answer_side_is_refused_… ... FAILED
```

This is the **third** instance of the repo's recurring shape — one fact, two spellings, both suites
green (`GAP-RT-WIRE-CONTEXT-ENCODING`, `GAP-SCHEMA-LABEL-SET-HASH-TWO-MEANINGS`). Fixed by a
hand-written `Deserialize` that refuses both, plus `SlotAnswer::answered()` so producers pair the
fields by construction: **zero `SlotAnswer` struct literals remain** in `crates/qd-runtime/src/`.
The same change made the answer side refuse unknown fields, which the request side already did —
the document had recorded that the two lanes chose differently.

**2. The crosslang guard ran, looked in the wrong place, and came back green.**
`crosslang_fixtures.py::inventory` searched a hardcoded tuple of four modules; `qd_wire` was not
among them, so `the_answer_side_has_no_python_parser_…` passed while a parser for all four
answer-side types sat three directories away. XLANG-PY found it, could not fix it (`crates/` is not
theirs) and pinned it as `GAP-XLANG-RS-GUARD-BLIND-TO-NEW-PACKAGE`. Adding `qd_wire` to the probe
made **two** guards fire with their own designed messages:

```
the_answer_side_has_no_python_parser_… ... FAILED  — "python/ grew a `SlotAnswer`"
python_has_no_span_value_type_…        ... FAILED  — "Python grew a SpanValue"
```

Both were then rewritten to assert the half they demanded, and the second renamed to
`the_three_span_spellings_stay_distinct_across_the_two_lanes` because its old name contradicted its
new assertion.

**3. `render.rs` claimed a cross-language pin that did not exist.**
The `ESCAPE_WORST_CASE_GROWTH` doc comment said `tests/render_contract.rs` pinned it against
Python. It does not, and could not: that file compares frozen golden prompt bytes captured from one
Python run, reads no Python file at test time, and its sample contains no escapable character. Its
`the_default_caps_are_self_consistent` calls only Rust's own `RenderCaps::validate()`. The values do
currently agree (both lanes 6; all five caps identical; identical floor formula — verified by direct
read of `python/qd_data/render.py`), so this was **unpinned risk, not live drift**.

A real pin now exists and needed no Python-side change, because `crosslang_fixtures.py` lives under
`crates/` and only *imports* `qd_data.render`:
`wire_context_crosslang.rs::the_escape_growth_bound_and_every_byte_cap_are_the_same_numbers_on_both_sides`
compares the constant, all five caps, and — by driving both validators at and just below Python's
floor — the floor **formula** rather than a second copy of the expression. Proven to bite by
temporarily restoring the historical split:

```
the_escape_growth_bound_… ... FAILED
  "the escape-growth bound differs between the lanes … GAP-RT-ESCAPE-GROWTH-FLOOR recurring"
  left: 6   right: 2
```

The constant was restored and the whole suite re-run green.

**4. The contract described a mechanism that does not exist.** `degraded` was documented as firing
"under thermal pressure with a raised threshold". `rg -ni thermal` (default **and**
`--no-ignore --hidden`) finds that word nowhere in the repository except that sentence. The three
real sources are named in the doc now: a non-model backend, a rebuilt-after-poison runtime, and a
slot-isolation check that could not run.
