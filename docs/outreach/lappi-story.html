Lappi · v0.1 preview · 6 October 2026

A 2B model that picks an option, or says it should not answer.

Lappi is a typed decision model fine-tuned from Qwen3.5-2B-Base. It never writes a sentence: each answer is one token read from 17 rows of its output layer. This page tells the story of its first 17 days, with the numbers it was held to.

Preview, not promoted: it missed 2 of 6 pre-registered lines

A full decision takes about 72 ms at a 124-token prompt and 2.3 s at 8,185 tokens on the M5 Pro. That is what the base model costs too: only the weights differ.

The bar it was held to

The released weights are the plain mean of five training seeds. Before the average was scored, a bar was written down: it had to be no worse than the weakest seed on six lines. It passed four.

The out-of-distribution line also fails its absolute bar of 90%. Prose got 60 of 60 abstentions, scrambled text 49 of 60, and unseen programming languages only 40 of 60. The span line fell because averaging blended five span heads that point in nearly unrelated directions, so this release does not serve span answers. The span line pools reading-comprehension answers and code-change evidence lines, and on the code rows it is a weak test: the diff's + markers show the changed lines (on an earlier run a pointer to a random added line scored 90.8% where the head scored 92.3%). The author released it as a preview anyway.

Serves

  • Choice questions with 2 to 16 options: routing, policy, evidence, NLI, reading, science, intent and multiple choice.
  • A calibrated score per answer, fitted per question width.
  • A typed refusal for any task it was not trained on.

Does not serve

  • Code-defect classification, the task it was built around: its trained request needs a span answer.
  • Span answers, and ordinal score slots.
  • Reliable 16-option answers: about half are refused, and calibration error there is 0.079, over its 0.05 limit.

Seventeen days

The first commit was on 19 September and the preview shipped on 6 October. The log holds 1,087 commits; 1,060 were co-written with AI coding agents working in parallel under written rules. The top rule: an agent may report that a gate failed, never move a threshold to make it pass.

  1. Cheapest model first. A 606K-parameter byte model trained from scratch set the floor. A linear classifier beat it in 17 of 18 comparisons (best 80.97% against 88.5%), which is what justified training the 2B.
  2. The 2B would not train on the Mac. A full run peaked at 80.8 GB on a 64 GB machine. Training moved to a rented GH200, then to two H100s; that last box billed about $463.
  3. Five versions of the corpus. The project's own checks found 215 validation questions overlapping MMLU and CommonsenseQA training rows. Abstain examples were rebuilt several times, because refusing one kind of strange input did not carry over to another.
  4. Gates that would not move. The run before the final one failed four. The final run failed out-of-distribution abstention on all five seeds. Definitions changed only by the author's recorded decisions, never by an agent.
  5. One heavy job at a time. The Mac kernel-panicked twice on 2 October; heavy jobs were serialised after that.

How the training differs

  • Labels by construction. Code-change rows come from a Rust mutation engine that edits real open-source files with tree-sitter, so each label and evidence line is a fact about the edit, not a model's guess.
  • Pre-registration. Every run's bar was committed before its result was read.
  • Controls. Shuffled-label training scored at chance on the four seeds where it ran. A per-family linear baseline is the bar to beat; the pooled version of that check could not run, one reason the preview is not promoted.
  • Held-out families. Two task families are never read in training: the trainer refuses their paths.
  • Plain recipe. Supervised fine-tuning only, no RL: one epoch of 12,176 steps per seed in PyTorch on two H100s, five seeds averaged.

  • Against Qwen3.5-2B it ties: the difference is +0.035 in Qwen's favour, interval [−0.039, +0.094].
  • Gemma 4 E4B, about four times larger, is clearly better: +0.200 [+0.133, +0.257].

  • On RM-Bench's code pairs it scores 0.111. Of 108 calls it said "tie" on 53, chose the broken program on 43 and the correct one on 12. Those pairs reach it as a "which answer is better" question, through its weakest family (pairwise helpfulness, 2% of training), not the code-defect question it was trained on.

Its own code question, on the same kind of programs

A diagnostic probe asked Lappi its trained code-defect question about each program, rendered as a whole-file diff. A pair counts as separated when the correct program gets the higher probability of clean.

It recognises the logic and stub mutations it was trained on (not cosmetic ones), but it does not tell RM-Bench's correct programs from the broken ones: it calls most of both clean. Before reading either arm, the probe checked that it reads the model correctly: 0.956 top-1 on all 2,304 validation rows of the code task, where the ledger has 0.950-0.958.

Gemma 4 E4B with reasoning on

On a 191-pair subset with no tie answers, scored against the other judges on the same pairs: Gemma 4 E4B reaches 0.816 with reasoning and 0.721 without, against 0.571 for Lappi (with reasoning minus Lappi: +0.245 [+0.122, +0.347]). With reasoning it takes about 14 s per verdict in the harness; Lappi takes about 0.24 s.

The full JevArena results

Other small typed-decision models appeared the week this started: TypeSafe's Jev, Bespoke's Nimble, and decider-2b on the same base model. Their published numbers use other tasks and metrics and were not run head to head here (a decider-2b run through the same harness has no result yet), so they are not ranked against Lappi.

What comes next

  • Serve the code-defect task: a release whose span calibration exists, or a trained choice-only request.
  • Rebuild the span head so it survives averaging: refit it on the averaged weights, keep one seed's head, or start every seed from one shared head. A refit, compared with one seed's head, is being set up first.
  • Fix abstention on unseen languages, and make the code-defect skill reach bugs it did not plant itself.
  • Publish the weights, model card and source. Each waits on the author's decision.
