# Can Lappi be done before 2026-09-28?

Asked on 2026-09-19. Nine days.

**Short answer: rung 0 plausibly yes. Rung 3 — the 2B — no, and not close.**

The rest of this document is the basis for that, because a schedule answer without its
evidence is a guess with a date attached.

### The one thing that unblocked this

`crates/qd-mutate/src/pool.rs`: *"A record with no hunks is a whole file with no diff
attached; every site in it is fair game"*, stamped `hunk_constrained: false` and counted
separately in the manifest.

So the mutation corpus **does not need commitpackft**, and therefore does not need Hugging
Face terms. It needs source files, and this machine has many. That moves the data blocker off
the critical path for rung 0 entirely.

The honesty cost is explicit and already handled by the crate: examples produced this way are
unconstrained samples, not hunk-constrained ones, and the manifest counts them separately.
Reporting the first as the second would be the "capped sample as complete coverage" failure.

## Why rung 3 cannot make the date

1. **Hugging Face terms are not accepted** — no weights, and this is a human action.
2. **Rule 4**: the 8xH100 block needs a wall-clock cap, a cost estimate and a human yes.
3. CPT then FT then eval then calibration is a multi-day sequence *after* data exists, and no
   shard has ever been built.
4. `GAP-SPAN-HEAD-LINE-MAPPING-BPE-UNVERIFIED` is still open for rung 3, and S4 predicted its
   refusal would fire widely the first time a real tokenizer ran. That is an unknown-size
   problem sitting on the path.

Even with terms accepted on 2026-09-20, this does not compress into eight days with one
human.

## What "done" has to mean

These are three different dates and conflating them is how a schedule becomes a fiction.

**(a) A trained rung-0 model with numbers in the ledger.** Plausible by 2026-09-28.

**(b) A model that clears its gates** — conformal coverage, abstain rate, kappa with a
bootstrap CI, ECE, plus the degenerate-head and shuffled-label controls. **Cannot be
promised**, because it depends on whether 600K byte-level parameters can actually do this
task, which is exactly what has not been measured. Rule 8 also applies: fewer than three
seeds is a `quick` row and **a `quick` row cannot promote anything**.

**(c) Rung 3, the 2B.** No.

If (a) lands and (b) does not, that is a *result*, not a slip: it would say the cheap rung is
insufficient and rung 2 or 3 is justified — which is the entire purpose of running the cheap
rung first.

## Named risks

- **Nobody has run qd-mutate end to end.** The ledger is empty. First runs surface problems;
  that is what first runs are for.
- **The adapter has a known hazard.** `qd-mutate` counts a **phantom final line** — `total_lines`
  is newline-count plus one, so a file ending in `\n` has a line at offset `len(text)` that
  `byte_context.line_starts` does not report. `span_from_byte_range` can legitimately return
  it for an edit appended at EOF. The adapter must refuse that case rather than clamp it.
  Found before writing the adapter; it still has to be handled correctly.
- **This repo has produced five instances of "one name, two quantities, both suites green."**
  The rate has not been dropping. Budget for a sixth.
- **A second session is active in this working tree.** Coordination is real overhead.

## What would actually move the date

For rung 0 — **nothing from you**. That is the point of the rung.

For rung 3: accept the Hugging Face terms, and be ready to approve one 8xH100 block with a
cap and a cost estimate. Neither puts rung 3 inside September.

## Outcome — 2026-09-28 (Measured and Verified)

Nine days after this question was asked, the outcome is recorded in the ledger and repository:

1. **(a) landed:** Rung 0 was built, trained, and measured across hundreds of rows in `ledger/`.
   The label generator `crates/qd-mutate`, pool builder, mutation adapter, and training harness
   ran end-to-end.
2. **(b) delivered its result:** The 606K byte-level model achieved 80.97% best accuracy
   (`AUDIT/capacity-and-learning-rate.md`), but trailed the char-n-gram linear control (88.5%) in
   17 of 18 arms in the controlled 144-row re-run (`ledger/gh200-operator-holdout-controlled-2026-09-22.jsonl`).
   As predicted above, this is a *result, not a slip*: it proved empirically that the cheap byte-level
   rung is insufficient for this task and that moving up the ladder to the 2B is justified by measurement.
3. **(c) Rung 3 started earlier than expected:**
   - Base weights `Qwen/Qwen3.5-2B-Base` were cached on disk.
   - Initial supervised fine-tuning completed on GH200 (`ledger/gh200-ft-commitpackft-2026-09-22.jsonl`)
     over ~2,000 commitpackft rows across 3 seeds. The score slot learned (54–55/90 vs 37 base).
   - `docs/train-plan-2026-09-28.md` defines the fast 2B training plan based on seven public peer models.
4. **Tooling and verification expanded:**
   - Pytest suite expanded from 981 to 1,784 passed tests (66 skipped, 0 failed).
   - Cargo workspace test suite expanded from 317 to 369 passed tests (0 failed).
   - Product website live at `https://lappi.vbcr.dev/`.
   - Private repository initialized and pushed to GitHub at `bharathvbcr/Lappi-decision`.
