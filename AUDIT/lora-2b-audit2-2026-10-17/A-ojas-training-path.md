6. AdamW over trainable subset on Metal: [V]
 - Per-tensor kernel is "check whole step then write only if finite" (device.rs:3277-3287 `ojas_adamw_check` then `ojas_adamw_apply`; backend.rs:2270-2300). It is NOT all-or-nothing across tensors: Trainer::apply loops tensors (trainer.rs:899-922), so a non-finite in tensor k leaves tensors < k updated and moments advanced. Lappi contract item 7 ("nothing moves after an Err before its first write") is unmet by composing these calls; a pre-pass (check all, then apply all) is needed in the new trainer/provider. gp-ft-trainer-loop criterion 8 stays open.
 - Frozen subset: Trainer skips `Moments::Frozen` slots (trainer.rs:822-860,:484) but binds them? card ft-2bbced18 says frozen moment slots are bound with g.param in BUILD_REPORT; I did not find that line in trainer.rs; not an issue for LoRA since no adapter Trainer exists.
 - clip_grad_norm: Backend::clip_grad_norm(&mut [Tensor], max) works over any slice (metal backend.rs:2048-2080): norm via device ClipNorm, non-finite -> NonFinite, scale in place only if scale<1. Over trainables only = caller passes only adapter grads (the GPT Trainer does at trainer.rs:746). OK in principle. Known issue: gp/clip-sq-norm (2146553, unmerged, worktree ojas-clipnorm) reimplements Metal clip through tessl's sq_norm; main still has the old kernel. Also grad_clip=0 is accepted and zeroes all gradients (validate accepts >=0, trainer.rs:226-231; clip_scale backend.rs:172) -- semantics-parity criterion still open. A trainable receiving no gradient fails the step (trainer.rs:858-861) -- still open.
 - Per-entry lr_scale/weight_decay: AdamWConfig is per call, so per-entry is natural; no OptimizerPlan equivalent for the Tape (groups.rs is ojas-qwen35, macOS only and tessl-typed).
