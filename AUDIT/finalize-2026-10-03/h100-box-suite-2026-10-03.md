**Bug 1: `tools/campaign_driver.py` `_cmdline` truncates the command line.**

- `ps -o command= -p PID` is cut at 80 columns by Linux procps when stdout is a pipe. macOS ps never
  cuts.
- So a finalizer or guard whose command line runs past column 80 reads as "not ours".
  - **[V]** On the box, the holder's command line came back as `…time.sleep(60) campaign_driver.p`.
  - A second finalizer then ran beside a live one.
  - `_is_guard` would read a live guard as dead.
- **Fix:** `ps -ww`.
- **Test:** the new `test_a_campaign_process_is_known_past_column_80`.
  - Pre-fix on the box, it and `test_only_one_process_finalizes` both fail.
  - Post-fix, the whole file passes.
- `rg` shows no other `ps -o command|args` use. The `pgrep -f` checks read the full command line.
- **The v5 lanes do not use `campaign_driver.py`**, so this does not block launch.

**Bug 2: my 8e6a009 left a test unupdated.**

- `main` passes `pre_dedupe_drops=` to `ft_split_rows`, and the exact-call expectation was never
  updated.
- **Fix:** the expectation gains `"pre_dedupe_drops": None`.
- **New test:** `test_main_hands_its_drop_list_to_ft_split_rows` checks that `--drop-before-dedupe`
  reaches the rebuild. Pre-fix main would drop it silently.
- This would have failed on the Mac too. The rebuild's Mac test runs covered `test_pre_dedupe_drops`,
  `test_decisions_pool` and `test_ft_linear_control`, not `test_real_ft_pieces`.

**Bug 3: three resolved gap records lack `question`.**

- The ids are GAP-V5-2GPU-COST-INSTANCE-RATE-REFUSED-AT-ONE-GPU, GAP-V5-2GPU-J5-PER-SEED-VS-RUNS-IFF
  and GAP-V5-2GPU-R9-HOLD-HOLDS-J5 (all -2026-10-03).
- Their resolved records on v5-build dropped `question`.
- **Fix:** append corrected records under the same ids (the current record plus its first record's
